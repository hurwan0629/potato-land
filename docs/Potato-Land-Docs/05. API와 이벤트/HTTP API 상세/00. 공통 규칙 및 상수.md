# HTTP API 상세 - 전역 규칙

## 1. 전역 규칙

### Base URL

```text
/api
```

### Cookie

```text
access_token
- 용도: 보호 API 인증
- TTL: 15분
- Path: /
- httpOnly: true
- sameSite: Lax
- secure: production true

refresh_token
- 용도: 토큰 재발급
- TTL: 7일
- Path: /api/auth/refresh
- httpOnly: true
- sameSite: Lax
- secure: production true
```

프론트 요청은 `credentials: "include"` 또는 axios `withCredentials: true`를 사용한다.

### JWT Claim

Access Token payload:

```json
{
  "sub": "1",
  "sid": "login_session_uuid",
  "jti": "access_token_uuid",
  "type": "access",
  "role": "USER",
  "iat": 0,
  "exp": 0
}
```

Refresh Token payload:

```json
{
  "sub": "1",
  "sid": "login_session_uuid",
  "jti": "refresh_token_uuid",
  "type": "refresh",
  "iat": 0,
  "exp": 0
}
```

Claim 의미:

| Claim | Access | Refresh | 의미 |
|---|---|---|---|
| `sub` | Y | Y | 사용자 `users.idx` 문자열 |
| `sid` | Y | Y | 로그인 세션 ID. 같은 로그인 세션의 access/refresh가 공유 |
| `jti` | Y | Y | 토큰 고유 ID |
| `type` | `access` | `refresh` | 토큰 용도 구분 |
| `role` | Y | N | `USER`, `ADMIN` |
| `iat` | Y | Y | 발급 시각 |
| `exp` | Y | Y | 만료 시각 |

검증 규칙:

- Access Token 검증 시 `type === "access"`를 확인한다.
- Refresh Token 검증 시 `type === "refresh"`를 확인한다.
- 보호 API에서는 access token 검증 후 DB에서 `deleted_at`, `banned_at`을 확인한다.
- 관리자 API에서는 access token의 `role`과 DB의 현재 role을 함께 확인한다.
- Refresh Token에는 `role`을 넣지 않는다. 재발급 시 DB에서 현재 role과 상태를 다시 조회한다.

Redis session key:

```text
session:{sub}:{sid}
```

Redis value 예시:

```json
{
  "currentRefreshJti": "refresh_token_uuid",
  "userAgent": "Mozilla/5.0",
  "ip": "127.0.0.1",
  "createdAt": "2026-07-30T13:00:00.000Z",
  "rotatedAt": "2026-07-30T13:10:00.000Z"
}
```

Redis TTL은 refresh token과 동일한 7일이다.

이 key의 존재와 `currentRefreshJti` 비교는 refresh 및 현재 세션 logout에서만 사용한다. 일반 보호 API의 Access Token 검증마다 Redis session을 조회하지 않는다.

Refresh rotation 규칙:

1. refresh JWT 서명과 `exp`를 검증한다.
2. `type === "refresh"`를 확인한다.
3. Redis `session:{sub}:{sid}`를 조회한다.
4. Redis의 `currentRefreshJti`와 refresh token의 `jti`를 비교한다.
5. 일치하면 새 access token과 새 refresh token을 발급한다.
6. Redis의 `currentRefreshJti`를 새 refresh token의 `jti`로 갱신한다.
7. 불일치하면 refresh token 재사용으로 보고 해당 세션을 삭제한다.

### 공통 실패 JSON 형태

```json
{
  "success": false,
  "code": "VALIDATION_ERROR",
  "message": "입력값을 확인해주세요.",
  "details": {
    "field": "loginId",
    "reason": "아이디는 필수입니다."
  }
}
```

`details`는 optional이다. 프론트에서 필드별 메시지가 필요하면 사용한다.

### 필드 이름과 페이지네이션

- HTTP의 params/query/body/response는 `camelCase`를 사용한다.
- PostgreSQL 컬럼과 SQL alias 이전 원본은 `snake_case`를 사용한다.
- 목록 query는 `page`, `limit`을 사용하고 `size`와 혼용하지 않는다.
- `page` 기본값은 1이다. 화면별 기본 `limit`은 상세 명세를 따르며 서버가 기본값을 적용한다.

목록 응답:

```json
{
  "success": true,
  "data": {
    "items": [],
    "page": 1,
    "limit": 16,
    "totalCount": 0,
    "totalPages": 0
  }
}
```

### 공통 상품 요약 DTO

중고·경매 목록, 메인, 관심목록, 마이페이지 카드가 같은 필드 이름을 사용한다. 경매에만 필요한 값은 `null` 또는 optional이다.

```json
{
  "listingIdx": 1,
  "listingType": "AUCTION",
  "title": "감자 키보드",
  "thumbnailUrl": "/resources/listings/1-1.png",
  "category": {
    "categoryIdx": 2,
    "name": "전자기기"
  },
  "displayPrice": 30000,
  "favoriteCount": 10,
  "status": "ON_GOING",
  "createdAt": "2026-08-03T00:00:00.000Z",
  "startedAt": "2026-08-03T00:00:00.000Z",
  "endsAt": "2026-08-04T00:00:00.000Z",
  "hasMyBid": true,
  "myBidAmount": 30000
}
```

`displayPrice`는 중고의 판매가, 경매의 현재가다. `hasMyBid`, `myBidAmount`는 optional 인증 사용자의 경매 카드에서만 사용한다.

### 공통 상품 상세 DTO

상세 응답은 요약 필드에 아래 구조를 추가한다.

```json
{
  "productStatus": "LIKE_NEW",
  "description": "상품 설명",
  "preferredTradeLocation": "서울 강남구",
  "images": [
    {
      "imageIdx": 1,
      "imageUrl": "/resources/listings/1-1.png",
      "sortOrder": 0
    }
  ],
  "seller": {
    "userIdx": 2,
    "nickname": "판매자",
    "profileImageUrl": "/resources/profiles/2.png",
    "averageRating": 9.2,
    "reviewCount": 14
  },
  "viewer": {
    "isOwner": false,
    "isFavorite": true,
    "canFavorite": true,
    "canChat": true,
    "canBid": true,
    "canEdit": false,
    "canDelete": false
  }
}
```

- 비로그인 상태에서 사용자 행동 권한은 모두 false다.
- `canBid`는 경매에서만 의미가 있다.
- 공개 상품 응답에 판매자의 이름, 전화번호, 이메일을 넣지 않는다.
- 상품 이미지는 `sortOrder` 오름차순으로 반환하며 등록·수정 후 최대 4장이다.

### 공통 에러 코드

| HTTP | code | 의미 |
|---:|---|---|
| 400 | `VALIDATION_ERROR` | 요청 형식 또는 필드 검증 실패 |
| 400 | `IMMUTABLE_FIELD` | 생성 후 바꿀 수 없는 필드 수정 시도 |
| 401 | `UNAUTHORIZED` | access token 없음, 만료, 위조 |
| 401 | `REFRESH_TOKEN_INVALID` | refresh token 없음, 만료, rotation 불일치 |
| 403 | `FORBIDDEN` | 로그인은 했지만 권한 없음 |
| 403 | `BANNED_USER` | 영구정지 사용자 |
| 404 | `NOT_FOUND` | 대상 없음 |
| 409 | `CONFLICT` | 중복, 상태 충돌 |
| 409 | `AUCTION_CLOSED` | 종료된 경매 |
| 409 | `BID_TOO_LOW` | 입찰가 부족 |
| 503 | `REDIS_UNAVAILABLE` | Redis 장애로 처리 불가 |
| 500 | `INTERNAL_SERVER_ERROR` | 서버 오류 |

## 2. 공통 상수

### AuthTokenType

```text
access
refresh
```

### UserRole

```text
USER
ADMIN
```

### PhoneAuthPurpose

```text
SIGNUP
FIND_ID
RESET_PASSWORD
CHANGE_PHONE
```

`CHANGE_PASSWORD`는 사용하지 않는다. 비밀번호 변경은 `POST /api/users/me/verify-password`로 받은 `verificationToken`을 사용한다.

### ListingType

```text
USED
AUCTION
```

### UsedTradeStatus

```text
ON_SALE
SOLD
```

중고글에는 `CANCELED`를 사용하지 않는다. 삭제는 `listings.deleted_at`으로 판단한다.

### ProductStatus

```text
NEW
LIKE_NEW
USED
DAMAGED
```

중고와 경매가 공통으로 사용하는 실제 상품 상태이며 상품 설명과 분리해 저장한다.

### AuctionStatus

```text
ON_GOING
FINISHED
```

경매글에는 `CANCELED`를 사용하지 않는다. 삭제는 `listings.deleted_at`으로 판단한다.

### TransactionStatus

```text
REQUESTED
COMPLETED
CANCELED
```

`CANCELED`는 판매자가 송금 요청을 취소하거나 사용자 비활성화 정리 과정에서 진행 요청을 취소할 때 사용한다.

### MessageType

```text
TEXT
IMAGE
PAYMENT_REQUEST
TRADE_COMPLETE
SYSTEM
```

MVP Socket 텍스트 전송은 `TEXT`를 사용한다. 이미지 메시지는 채팅 이미지 업로드 API를 사용한다.

### NotificationType

```text
NEW_CHAT_ROOM
NEW_MESSAGE
PAYMENT_REQUESTED
PAYMENT_RECEIVED
PAYMENT_CANCELED
NEW_REVIEW
NEW_BID
OUTBID
AUCTION_WON
AUCTION_ENDED
AUCTION_ENDED_WITHOUT_BID
AUCTION_LEADER_CHANGED
LISTING_DELETED
```

### NotificationReferenceType

```text
CHAT_ROOM
CHAT_MESSAGE
LISTING

```

### SocketRoomName

```text
user:{userIdx}
chat:{chatRoomIdx}
auction:{listingIdx}
```

### RedisKey

```text
session:{sub}:{sid}
phone:code:{phone}:{purpose}
phone:verified:{phone}:{purpose}
phone:cooldown:{phone}:{purpose}
auction:state:{listingIdx}
```

Redis presence, Redis auction participants, `req.validated`, `socket.data.joinedRooms`는 사용하지 않는다.

`phoneVerificationId`는 전화번호 인증 흐름을 다른 요청과 구분하는 공개 식별자로 사용한다. Redis key 이름에는 넣지 않고 `phone:code:*`, `phone:verified:*` value 안에 저장해 요청값과 일치하는지 확인한다.
