# 2026-08-01 구현 계약 및 상태 정합성 개정

## 목적

프론트 요청, Express 검증, PostgreSQL 영속 상태, Redis 실시간 상태, Socket 이벤트가 같은 정책을 사용하도록 문서를 구현 순서 중심으로 개정했다.

## 확정 정책

- 중고 등록은 `POST /api/used`, 경매 등록은 `POST /api/auction`을 사용한다.
- 후기 rating은 API/DB 정수 1~10, UI만 `/ 2`해 0.5~5점으로 표시한다.
- 경매 종료는 낙찰만 확정하며 거래/채팅을 자동 생성하지 않는다.
- 판매자가 낙찰자를 대상으로 송금 요청을 만들 때 거래와 정산 채팅을 생성 또는 재사용한다.
- 종료 경매의 일반 신규 채팅은 차단하고 판매자·낙찰자 정산 채팅만 거래 상태에 따라 허용한다.
- 거래 완료 부수효과는 중고 `SOLD`, 판매자 알림 `PAYMENT_RECEIVED`, 시스템 메시지 `TRADE_COMPLETE`로 통일한다.
- 송금 요청 취소 알림은 `PAYMENT_CANCELED`로 통일한다.
- 회원가입 전화번호 reservation key를 폐기하고 verified key와 DB UNIQUE를 사용한다.
- Redis 경매 Hash는 `currentPrice`, `highestBidderIdx`, `highestBidIdx`만 저장한다.

## 구현 흐름 개정

- `09. 구현 흐름/` 전체 파일에 요청 계약과 계층별 처리 순서를 명시했다.
- DB transaction에 포함되는 핵심 상태·알림·시스템 메시지와 commit 이후 Redis/Socket 작업을 구분했다.
- Socket은 영속 원본이 아니며 재연결·누락 시 HTTP로 복구하도록 고정했다.
- `bidIdx`, `messageIdx`, `clientMessageId`로 중복·역순·재전송을 처리하도록 명시했다.
- Redis 성공 후 DB 실패의 완전한 보상은 MVP 범위에서 제외하되 best-effort 복구와 향후 reconciliation/outbox 확장 경계를 남겼다.

## 단순화

- Redis presence와 경매 참여자 목록을 사용하지 않는다.
- 경매 상태·종료 시각·입찰 이력·알림·평점을 Redis에 중복 저장하지 않는다.
- 관리자 삭제는 별도 구현하지 않고 도메인 삭제 서비스를 재사용한다.
- 실시간 관리자 통계, Redis 통계 캐시, Redis Stream/Worker, 분산 transaction은 MVP에 도입하지 않는다.

## 검증 기준

- 활성 문서에서 폐기된 알림 타입·Redis key·경매 등록 endpoint가 남지 않아야 한다.
- 공통 상수, ERD enum, HTTP 알림 API, Socket 알림 목록이 같은 타입 집합을 사용해야 한다.
- DB commit 전 성공 Socket 이벤트를 전송하지 않아야 한다.
- 경매 종료, 거래 생성, 거래 완료를 서로 다른 상태 전이로 유지해야 한다.
