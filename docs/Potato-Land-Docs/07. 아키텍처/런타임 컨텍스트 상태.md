# 런타임 컨텍스트 상태

> 구현 시 변수명과 임시 상태 저장 위치를 고정하기 위한 기준 문서다.
> Express middleware, Socket.IO middleware, Redis service, controller/service 사이에서 사용하는 상태 이름은 이 문서를 따른다.

## 1. 원칙

- PostgreSQL이 최종 신뢰 기준이다.
- Redis는 refresh session, 전화번호 인증, 진행 중 경매의 현재 입찰 상태만 관리한다.
- Socket 현재 화면 상태는 `socket.data`에만 둔다.
- 보호 API와 Socket 연결 시에는 항상 사용자 `deleted_at`, `banned_at`을 확인한다.
- Service는 Express `req` 또는 Socket 객체 전체를 직접 받지 않는다.
- Controller는 `req.body`, `req.query`, `req.params`, `req.user`, `req.file`, `req.files`, `req.requestId`에서 필요한 값만 Service에 명시적으로 넘긴다.

## 2. Express Request 확장

### 2.1 `req.auth`

JWT 검증 결과를 담는다. 인증 middleware 내부와 로그/디버깅에서 사용한다.

```js
req.auth = {
  tokenType: 'access',
  sub: '1',
  userIdx: 1,
  sid: 'login_session_uuid',
  jti: 'access_token_uuid',
  role: 'USER',
  iat: 1785416400,
  exp: 1785417300
};
```

규칙:

- `tokenType`은 JWT claim `type`을 내부 변수명으로 풀어쓴 값이다.
- Access Token만 `role`을 가진다.
- Refresh API에서는 `req.auth.tokenType = 'refresh'`가 될 수 있다.
- 일반 보호 API에서는 `req.auth.tokenType !== 'access'`이면 `UNAUTHORIZED`다.

### 2.2 `req.user`

DB에서 현재 사용자 상태까지 확인한 뒤 만든다. Controller와 Service의 사용자 기준 값이다.

```js
req.user = {
  userIdx: 1,
  loginId: 'potato123',
  nickname: '감자왕',
  role: 'USER',
  profileImageUrl: '/resources/profiles/1.png',
  deletedAt: null,
  bannedAt: null,
  bannedUntil: null,
  isActive: true,
  isAdmin: false
};
```

규칙:

- `req.user`는 보호 API에서 필수다.
- `req.user.isActive === false`이면 보호 API를 통과시키지 않는다.
- 관리자 API는 `req.user.isAdmin === true`를 요구한다.
- 일반 화면에서 비활성 사용자를 표시해야 할 때는 `req.user`가 아니라 조회 대상 사용자 DTO에서 `displayName = '삭제된 사용자'`를 만든다.

### 2.3 `req.file`

단일 파일 업로드에서 사용한다.

```js
req.file = {
  fieldname: 'profileImage',
  originalname: 'profile.png',
  mimetype: 'image/png',
  size: 12345,
  filename: 'generated-file-name.png',
  path: 'uploads/profiles/generated-file-name.png',
  publicUrl: '/resources/profiles/generated-file-name.png'
};
```

사용 API:

- `PATCH /api/users/me/profile`
- `POST /api/chats/:chatRoomIdx/messages/images`

### 2.4 `req.files`

여러 파일 업로드에서 사용한다.

```js
req.files = [
  {
    fieldname: 'images',
    originalname: 'item-1.png',
    mimetype: 'image/png',
    size: 12345,
    filename: 'listing-1-1.png',
    path: 'uploads/listings/listing-1-1.png',
    publicUrl: '/resources/listings/listing-1-1.png'
  }
];
```

사용 API:

- `POST /api/used`
- `PATCH /api/used/:listingIdx`
- `POST /api/auctions`
- `PATCH /api/auctions/:listingIdx`

### 2.5 `req.requestId`

로그 추적용 요청 ID다.

```js
req.requestId = 'req_01HZX...';
```

규칙:

- 요청 시작 middleware에서 생성한다.
- 에러 로그, DB 로그, Socket emit 로그에 함께 남긴다.

## 3. Controller에서 Service로 넘기는 값

요청 검증 middleware는 `req.body`, `req.query`, `req.params`를 검증하고 필요한 타입으로 정리한다.
별도 `req.validated` 객체는 만들지 않는다.

권장 형태:

```js
await usedService.createUsed({
  actor: req.user,
  body: req.body,
  files: req.files,
  requestId: req.requestId
});
```

공통 이름:

| 이름 | 의미 |
|---|---|
| `actor` | 현재 요청을 수행하는 로그인 사용자 |
| `body` | 검증된 body |
| `query` | 검증된 query |
| `params` | 검증된 params |
| `file` | 단일 업로드 파일 |
| `files` | 복수 업로드 파일 |
| `requestId` | 로그 추적 ID |

## 4. Socket.IO `socket.data`

### 4.1 `socket.data.auth`

Socket 인증 middleware가 access token을 검증한 결과다.

```js
socket.data.auth = {
  tokenType: 'access',
  sub: '1',
  userIdx: 1,
  sid: 'login_session_uuid',
  jti: 'access_token_uuid',
  role: 'USER',
  iat: 1785416400,
  exp: 1785417300
};
```

### 4.2 `socket.data.user`

Socket 인증 middleware가 DB 사용자 상태까지 확인한 값이다.

```js
socket.data.user = {
  userIdx: 1,
  loginId: 'potato123',
  nickname: '감자왕',
  role: 'USER',
  profileImageUrl: '/resources/profiles/1.png',
  deletedAt: null,
  bannedAt: null,
  bannedUntil: null,
  isActive: true,
  isAdmin: false
};
```

규칙:

- `socket.data.user.isActive === false`이면 연결하지 않는다.
- 관리자 영구정지 또는 회원 탈퇴 시 해당 사용자의 Socket 연결은 강제 종료한다.

### 4.3 `socket.data.activeChatRoomIdx`

사용자가 현재 보고 있는 채팅방이다.

```js
socket.data.activeChatRoomIdx = 1;
```

규칙:

- `chat:join` 성공 시 설정한다.
- 설정 전 기존 auction room을 leave하고 `activeAuctionListingIdx`를 null로 만든다.
- `chat:leave` 또는 연결 종료 시 `null`로 정리한다.
- 수신자의 연결 중 하나라도 해당 `chatRoomIdx`를 보고 있으면 `NEW_MESSAGE` notification row를 만들지 않는다.
- Redis presence key는 사용하지 않는다.

### 4.4 `socket.data.activeAuctionListingIdx`

사용자가 현재 보고 있는 경매 상세다.

```js
socket.data.activeAuctionListingIdx = 2;
```

규칙:

- `auction:join` 성공 시 설정한다.
- 설정 전 기존 chat room을 leave하고 `activeChatRoomIdx`를 null로 만든다.
- `auction:leave` 또는 연결 종료 시 `null`로 정리한다.
- 경매 종료/낙찰/삭제/최고입찰자 변경 알림은 사용자가 상세 화면을 보고 있어도 DB에 남긴다.
- Redis presence key는 사용하지 않는다.

## 5. Socket Room 이름

```text
user:{userIdx}
chat:{chatRoomIdx}
auction:{listingIdx}
```

예시:

```text
user:1
chat:10
auction:20
```

Room join 여부를 별도 `socket.data.joinedRooms`에 저장하지 않는다.
필요하면 Socket.IO adapter의 room 상태를 조회하거나, join/leave 처리 함수 내부에서 즉시 정리한다.

## 6. Redis Key 명세

### 6.1 Refresh Session

Key:

```text
session:{sub}:{sid}
```

예시:

```text
session:1:login_session_uuid
```

Value:

```json
{
  "currentRefreshJti": "refresh_token_uuid",
  "userAgent": "Mozilla/5.0",
  "ip": "127.0.0.1",
  "createdAt": "2026-07-31T00:00:00.000Z",
  "rotatedAt": "2026-07-31T00:10:00.000Z"
}
```

TTL: 7일

삭제 조건:

- 로그아웃
- refresh token 재사용 탐지
- 회원 탈퇴
- 관리자 영구정지

### 6.2 Phone Auth Code

Key:

```text
phone:code:{phone}:{purpose}
```

예시:

```text
phone:code:01012345678:SIGNUP
```

Value:

```json
{
  "phone": "01012345678",
  "purpose": "SIGNUP",
  "phoneVerificationId": "phone-verification-uuid",
  "codeHash": "hashed-code",
  "attemptCount": 0,
  "createdAt": "2026-07-31T00:00:00.000Z",
  "expiresAt": "2026-07-31T00:03:00.000Z"
}
```

TTL: 3분

규칙:

- 인증번호 원문은 저장하지 않는다.
- `codeHash`는 입력 인증번호를 같은 방식으로 해싱해 비교한다.
- `attemptCount`가 허용 횟수를 초과하면 검증을 차단하고 code key를 삭제한다.
- 같은 `phone + purpose`로 재발송하면 새 `phoneVerificationId`와 코드로 value를 덮어써 이전 인증 시도를 무효화한다.

### 6.3 Phone Auth Cooldown

Key:

```text
phone:cooldown:{phone}:{purpose}
```

Value:

```json
{
  "phone": "01012345678",
  "purpose": "SIGNUP",
  "resendAfterSeconds": 30
}
```

TTL: 30초

### 6.4 Phone Verified

Key:

```text
phone:verified:{phone}:{purpose}
```

Value:

```json
{
  "phone": "01012345678",
  "purpose": "SIGNUP",
  "phoneVerificationId": "phone-verification-uuid",
  "verified": true,
  "verifiedAt": "2026-07-31T00:02:00.000Z"
}
```

TTL: 10분

소비 조건:

- 회원가입 성공
- 비밀번호 재설정 성공
- 전화번호 변경 성공

최종 목적 API는 요청의 `phoneVerificationId`가 value와 일치할 때만 성공할 수 있다. 성공한 DB commit 뒤 `phone:verified:{phone}:{purpose}`를 삭제하며, 별도 DELETE status API는 두지 않는다.

### 6.5 Auction State

Key:

```text
auction:state:{listingIdx}
```

예시:

```text
auction:state:2
```

Redis Hash fields:

```text
currentPrice       20000
highestBidderIdx   3
highestBidIdx      10
```

규칙:

- Redis auction state는 진행 중 입찰의 빠른 검증과 원자 갱신에만 사용한다.
- `status`, `startPrice`, `endsAt`, `bidCount`, `minNextBid`, `updatedAt`은 Redis에 저장하지 않는다.
- `minNextBid`는 현재가와 서버의 입찰 증가 규칙으로 계산한다.
- 경매 상태, 시작가, 종료 시간은 DB를 기준으로 조회한다.
- 입찰자 목록은 Redis에 저장하지 않고 `auction_bids`에서 조회한다.
- 구현 단순화를 위해 TTL 없이 두고 종료/삭제 시 명시 삭제한다.

삭제 조건:

- 경매 종료 후 DB 확정과 알림 전송 완료
- 경매 soft delete
- 판매자 탈퇴/영구정지로 진행 중 경매 삭제

## 7. Timer 상태

서버 메모리에서 관리하는 Timer map 이름은 `auctionTimers`로 고정한다.

```js
auctionTimers = new Map([
  [
    2,
    {
      listingIdx: 2,
      timeoutId: timeoutObject
    }
  ]
]);
```

규칙:

- 경매 생성 시 DB `auction_posts.ends_at` 기준으로 timeout을 계산한다.
- 경매 생성 시 `auctionTimers.set(listingIdx, timerState)`를 수행한다.
- 경매 종료 시 `auctionTimers.delete(listingIdx)`를 수행한다.
- 경매 삭제 시 `clearTimeout(timeoutId)` 후 삭제한다.
- 서버 시작 시 DB의 `ON_GOING`이고 `deleted_at IS NULL`인 경매만 복원한다.
- 종료 시각 원본은 DB `auction_posts.ends_at`이다.

## 8. DTO 표시 상태

### 8.1 비활성 사용자 표시

일반 사용자 화면 DTO에서 비활성 사용자는 다음 형태로 내려준다.

```js
userSummary = {
  userIdx: 2,
  displayName: '삭제된 사용자',
  nickname: null,
  profileImageUrl: null,
  profileEnabled: false,
  inactive: true
};
```

활성 사용자는 다음 형태다.

```js
userSummary = {
  userIdx: 2,
  displayName: '감자왕',
  nickname: '감자왕',
  profileImageUrl: '/resources/profiles/2.png',
  profileEnabled: true,
  inactive: false
};
```

### 8.2 삭제 상품 표시

완료 거래내역에서 삭제 상품은 snapshot 형태로 보여준다.

```js
listingSnapshot = {
  listingIdx: 1,
  title: '감자 키보드',
  thumbnailUrl: '/resources/listings/1-1.png',
  displayPrice: 10000,
  deleted: true,
  detailLinkEnabled: false
};
```

일반 목록/검색/마이페이지/외부 프로필/관심목록에서는 삭제 상품을 응답하지 않는다.

## 9. 신뢰 기준

| 상태 | 저장 위치 | 신뢰 수준 | 사용처 |
|---|---|---|---|
| 사용자 탈퇴/정지 | PostgreSQL `users` | 최종 기준 | 모든 보호 API, Socket 연결 |
| 게시글 삭제 | PostgreSQL `listings.deleted_at` | 최종 기준 | 목록/상세/채팅/입찰/관심 |
| 거래 상태 | PostgreSQL `transactions.status` | 최종 기준 | 송금/후기/거래내역 |
| 경매 상태/종료 시간 | PostgreSQL `auction_posts` | 최종 기준 | 상세/종료/복구 |
| 경매 현재 입찰 상태 | Redis `auction:state:{listingIdx}` + PostgreSQL | 입찰 중 Redis projection, DB 영속 원본 | 입찰/상세/종료 |
| refresh session | Redis `session:{sub}:{sid}` | 인증 기준 | refresh/logout |
| 전화번호 인증 | Redis `phone:*:{phone}:{purpose}` | 임시 인증 기준 | 회원가입/비밀번호/전화번호 변경 |
| 현재 채팅방/경매 화면 | `socket.data.activeChatRoomIdx`, `socket.data.activeAuctionListingIdx` | 임시 상태 | NEW_MESSAGE 저장 생략, 화면 room 관리 |
