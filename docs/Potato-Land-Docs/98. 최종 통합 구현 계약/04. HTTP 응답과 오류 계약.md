# HTTP 응답과 오류 계약

## 1. 성공 응답

```json
{
  "success": true,
  "data": {}
}
```

삭제·수정도 가능한 한 결과 상태를 `data`에 명시한다.

## 2. 실패 응답

```json
{
  "success": false,
  "code": "VALIDATION_ERROR",
  "message": "입력값을 확인해주세요.",
  "details": {
    "fields": ["title"]
  }
}
```

## 3. 오류 코드 원칙

| status | 대표 code | 의미 |
|---:|---|---|
| 400 | `VALIDATION_ERROR` | 형식·범위 오류 |
| 401 | `UNAUTHORIZED` | 인증 없음·만료·탈퇴 계정 |
| 403 | `FORBIDDEN`, `BANNED_USER` | 권한 없음·정지 계정 |
| 404 | `NOT_FOUND` | 공개 가능한 대상 없음 |
| 409 | `CONFLICT`, `AUCTION_CLOSED` | 중복·상태 충돌 |
| 410 | `PHONE_VERIFICATION_EXPIRED` | 소비되거나 만료된 인증 증명 |
| 500 | `INTERNAL_SERVER_ERROR` | 노출하지 않는 서버 오류 |

`AppError`는 객체 인자를 정본으로 사용한다.

```js
throw new AppError({
  status: 409,
  code: "CONFLICT",
  message: "이미 처리된 요청입니다.",
  details: { transactionIdx },
});
```
