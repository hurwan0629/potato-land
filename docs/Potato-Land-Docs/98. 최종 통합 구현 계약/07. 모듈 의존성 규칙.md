# 모듈 의존성 규칙

## 허용 방향

```text
router
  → middleware / infrastructure upload
  → controller
  → service
  → repository
  → infrastructure database
```

Service는 공통 Redis·Socket emitter·scheduler를 사용할 수 있다. Repository는 다른 도메인의 Controller나 HTTP 객체를 참조하지 않는다.

## 금지 사례

- `modules/chats/chat.upload.js`처럼 도메인마다 Multer storage를 새로 정의
- `modules/*/env/db.js`처럼 공통 DB Pool을 다시 생성
- Controller에서 수백 줄 SQL과 transaction을 직접 작성
- Repository에서 `req`, `res`, `io` 사용
- Socket handler에서 HTTP Controller 재사용
- raw room 문자열 `auction_${id}`, `chat_${id}` 사용

## 확장 가능한 방식

새 도메인 추가 시 아래 파일 구성을 기본으로 한다.

```text
modules/example/
├─ example.router.js
├─ example.controller.js
├─ example.service.js
├─ example.repository.js
└─ example.validator.js
```

공통 기능은 두 도메인 이상에서 필요해질 때 `common` 또는 `infrastructure`로 올린다.
