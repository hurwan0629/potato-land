# 핵심 URL 실행 흐름

## 회원정보 수정

1. 사용자가 현재 비밀번호를 확인한다.
2. 서버가 10분 `editToken`을 발급한다.
3. 수정 요청에서 `editToken`을 검증한다.
4. 전화번호가 변경되면 `CHANGE_PHONE`의 `phoneVerificationId`를 추가 검증한다.
5. 중복 정보와 새 비밀번호 정책을 확인한다.
6. DB를 수정한다.
7. 전화 proof를 소비하고 비밀번호 변경 시 모든 Refresh session을 삭제한다.

```text
POST /api/users/me/verify-password
→ requireAuth
→ users.controller.verifyMyPassword
→ users.service.verifyAccountPassword
→ users.repository.findEditableUser
→ bcrypt.compare
→ createEditToken(userIdx)

PATCH /api/users/me
→ requireAuth
→ users.controller.updateMe
→ validateAccountUpdate
→ verifyEditToken
→ getPhoneVerified(phone, CHANGE_PHONE)
→ findProfileConflict
→ updateUserAccount
→ deletePhoneVerified / deleteAllRefreshSessions
```

## 중고 등록

1. 현재 사용자 상태를 인증한다.
2. 공통 upload middleware가 이미지 최대 4장을 저장한다.
3. 상품 입력과 카테고리·가격을 검증한다.
4. `listings`, `used_posts`, `post_images`를 한 transaction에서 생성한다.
5. 생성된 `listingIdx`를 반환한다.

```text
POST /api/used
→ requireAuth
→ infrastructure/uploads.listingImageUpload
→ used.controller.createUsed
→ used.service.createUsedListing
→ used.validator.validateUsedCreate
→ used.repository.insertUsedListing
→ withTransaction
```

## 경매 입찰

1. 현재 사용자를 인증한다.
2. 경매 ID와 입찰 금액을 검증한다.
3. PostgreSQL에서 `auction_posts` 행을 `FOR UPDATE`로 잠근다.
4. 삭제·종료·판매자 본인·최소 입찰가를 확인한다.
5. `auction_bids`를 저장하고 현재가를 갱신한 뒤 commit한다.
6. Redis state와 bidders sorted set을 갱신한다.
7. 경매 room과 이전 최고 입찰자 개인 room으로 Socket event를 보낸다.

```text
POST /api/auctions/:listingIdx/bids
→ requireAuth
→ auctions.controller.createAuctionBid
→ auctions.service.createAuctionBid
→ validateListingIdx / validateBidAmount
→ auctions.repository.insertBid
→ SELECT ... FOR UPDATE
→ INSERT auction_bids / UPDATE auction_posts
→ Redis auction:{listingIdx}:state
→ Redis ZADD auction:{listingIdx}:bidders
→ auction:bid-updated / auction:leader-changed / auction:outbid
```

## 경매 종료와 서버 복구

1. Timer 또는 recovery scheduler가 `finalizeAuction`을 호출한다.
2. 경매 행을 잠그고 이미 종료됐으면 멱등 종료한다.
3. 활성 최고 입찰자를 선택한다.
4. `FINISHED`, `winning_bid_idx`, 낙찰 거래, 알림을 transaction으로 저장한다.
5. commit 후 Timer와 Redis를 제거한다.
6. 판매자·낙찰자·미낙찰 입찰자에게 알림과 Socket event를 보낸다.

```text
server.startServer
→ connectDatabase / connectRedis
→ recoverAuctions
→ startAuctionRecoveryScheduler(recoverAuctions)
→ scheduleAuctionEnd(listingIdx, endsAt, finalizeAuction)
```

## 관리자 회원 정지

1. `requireAuth`로 현재 DB 사용자를 확인한다.
2. `requireRole(ADMIN)`으로 역할을 확인한다.
3. 관리자 본인 정지를 차단한다.
4. 요청 거래 취소, 소유 상품 삭제, 활성 입찰 제거·현재가 재계산, 사용자 정지를 transaction으로 처리한다.
5. commit 후 Refresh session, Timer, Redis를 정리한다.
