# Redis Socket Scheduler 계약

## 1. Redis key

| key | 값 | 목적 |
|---|---|---|
| `session:sub:{sessionId}` | Refresh session JSON | rotation과 폐기 |
| `phone:{normalizedPhone}:{purpose}:code` | 인증번호 상태 | SMS 확인 |
| `phone:{normalizedPhone}:{purpose}:verified` | `phoneVerificationId` 포함 proof | 인증 완료 |
| `auction:{listingIdx}:state` | 현재가·최고 입찰자·종료 시각 | 빠른 실시간 조회 cache |
| `auction:{listingIdx}:lock` | 짧은 TTL lock | 중복 종료 방지 보조 |

DB가 경매 입찰의 최종 source of truth다. Redis는 cache와 복구 보조 수단이다.

## 2. Socket room

| room | 용도 |
|---|---|
| `user:{userIdx}` | 개인 알림 |
| `chat:{chatRoomIdx}` | 채팅방 |
| `auction:{listingIdx}` | 경매 실시간 정보 |

room 문자열은 `common/constants/socketRoom.js`만 사용한다.

## 3. 입찰 흐름

1. 인증 사용자와 경매 room 접근 권한을 확인한다.
2. DB transaction에서 경매 row를 `FOR UPDATE`로 잠근다.
3. 판매자 본인, 종료 상태, 최소 입찰가를 확인한다.
4. 입찰을 저장하고 현재가를 갱신한다.
5. commit한다.
6. Redis cache를 갱신한다.
7. `auction:bid-updated`, 필요하면 `auction:leader-changed`를 전파한다.
8. 이전 최고 입찰자에게 `OUTBID` 알림을 보낸다.

## 4. Recovery scheduler

서버 시작 후 반드시 scheduler를 시작한다.

1. 종료 시각이 지났지만 `ON_GOING`인 경매를 조회한다.
2. 공통 종료 service를 호출한다.
3. 미래 경매 Timer를 다시 등록한다.
4. 여러 인스턴스가 동시에 실행해도 row lock과 상태 조건으로 한 번만 완료된다.
