## 1. 목적

회원가입에 사용되는 전화번호의 소유 여부를 확인한다.

## 2. 액터

### 주 액터
- 비회원

### 외부 지원 액터
- 문자 발송 서비스

## 3. 사전 조건

- 올바른 형식의 전화번호를 입력했다.
- 해당 전화번호로 가입된 계정이 없다.
- 인증번호 발송 제한에 걸리지 않았다.

## 4. 정상 플로우

1. 사용자가 전화번호를 입력한다.
2. 인증번호 발송을 요청한다.
3. 서버가 전화번호 형식과 중복 여부를 확인한다.
4. 서버가 인증번호를 생성한다.
5. 인증번호를 Redis에 3분 동안 저장한다.
6. 문자 발송 서비스를 통해 인증번호를 전송한다.
7. 사용자가 인증번호를 입력한다.
8. 서버가 Redis의 인증번호와 비교한다.
9. 인증에 성공하면 인증번호 정보를 삭제한다.
10. 인증 완료 식별자를 새로 생성한다.
11. 인증 완료 정보를 Redis에 10분 동안 저장한다.
12. 서버가 인증 완료 식별자를 클라이언트에 전달한다.
13. 프론트는 전화번호와 인증번호 입력 영역을 비활성화한다.

## 5. 대체 플로우

- 사용자가 인증 완료 상태를 취소하고 전화번호를 다시 입력한다.
- 새로고침 후 서버에 인증 상태를 조회하여 완료 화면을 복원한다.
- 인증번호를 재발송하면 이전 인증번호는 무효화한다.

## 6. 예외 플로우

- 잘못된 전화번호 형식
- 이미 가입된 전화번호
- 인증번호 불일치
- 인증번호 만료
- 검증 시도 횟수 초과
- 인증번호 발송 횟수 초과
- 너무 빠른 재발송 요청
- 문자 발송 서비스 오류

## 7. 상태 변화

UNVERIFIED
→ CODE_SENT
→ VERIFIED
→ CONSUMED

실패 상태:
- EXPIRED
- BLOCKED

## 8. 만료 정책

- 인증번호 유효 시간: 3분
- 인증 완료 식별자 유효 시간: 10분
- 재발송 대기 시간: 미정
- 인증번호 최대 검증 횟수: 미정

## 9. 관련 API

- 인증번호 발송
- 인증번호 검증
- 현재 인증 상태 조회
- 인증 완료 상태 초기화

## 10. 클라이언트 처리

- 인증 성공 시 전화번호 입력 비활성화
- 인증번호 입력 비활성화
- 발송 및 인증 버튼 비활성화
- 인증 완료 메시지 표시
- 인증 만료 시 다시 입력할 수 있도록 변경

## 11. 보안

- 인증번호를 로그에 출력하지 않는다.
- Redis에 인증번호 평문 대신 해시 저장을 고려한다.
- (여유 되면) 전화번호별 요청 횟수를 제한한다.
- (여유 되면) IP별 요청 횟수를 제한한다.
- 인증 완료 식별자는 예측할 수 없는 난수로 생성한다.
- 인증 완료 정보는 회원가입 성공 시 한 번만 사용한다.
- 쿠키는 Httponly와 SameSite가 적용된 쿠키로 이루어진다.

## 12. 미결정 사항

- 재발송 대기 시간
- 최대 검증 시도 횟수
