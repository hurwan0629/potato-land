# A-03 전화번호 인증

## 1. 목적

회원가입, 아이디 찾기, 비밀번호 재설정, 전화번호 변경에 사용되는 전화번호의 소유 여부를 확인한다.

## 2. 액터

### 주 액터

- 비회원
- 로그인 사용자

### 외부 지원 액터

- 문자 발송 서비스

## 3. 사전 조건

- 올바른 형식의 전화번호를 입력했다.
- 목적별 검증 조건을 만족한다.
- 인증번호 발송 제한에 걸리지 않았다.

## 4. 인증 목적

- `SIGNUP`: 회원가입
- `FIND_ID`: 아이디 찾기
- `RESET_PASSWORD`: 비밀번호 재설정
- `CHANGE_PHONE`: 내 정보 수정에서 전화번호 변경

비밀번호 변경은 전화번호 인증 목적을 사용하지 않는다. 내 정보 수정 전 비밀번호 확인으로 발급받은 `verificationToken`을 사용한다.

## 5. 정상 플로우

1. 사용자가 전화번호와 인증 목적 `purpose`를 입력한다.
2. 프론트가 `POST /api/auth/phone/send`에 `phone`, `purpose`를 보낸다.
3. 서버가 전화번호 형식과 목적별 검증 조건을 확인한다.
4. 서버가 인증번호를 생성한다.
5. 서버가 인증번호 원문이 아니라 hash를 Redis `phone:code:{phone}:{purpose}`에 저장한다.
6. 서버가 Redis `phone:cooldown:{phone}:{purpose}`를 30초 TTL로 저장한다.
7. 문자 발송 서비스를 통해 인증번호를 전송한다.
8. 사용자가 인증번호를 입력한다.
9. 프론트가 `POST /api/auth/phone/verify`에 `phone`, `purpose`, `code`를 보낸다.
10. 서버가 Redis의 `codeHash`와 입력 인증번호 hash를 비교한다.
11. 인증 성공 시 서버가 Redis `phone:verified:{phone}:{purpose}`를 10분 TTL로 저장한다.
12. `SIGNUP` 목적이면 Redis `phone:reservation:{phone}:SIGNUP`도 10분 TTL로 저장한다.
13. 프론트는 전화번호와 인증번호 입력 영역을 비활성화한다.

`phoneVerificationId`는 사용하지 않는다.

## 6. 대체 플로우

- 사용자가 인증 완료 상태를 취소하고 전화번호를 다시 입력한다.
- 새로고침 후 서버에 `phone`, `purpose`로 인증 상태를 조회하여 완료 화면을 복원한다.
- 인증번호를 재발송하면 같은 `phone + purpose`의 이전 인증번호는 무효화한다.

## 7. 예외 플로우

- 잘못된 전화번호 형식
- 목적별 조건에 맞지 않는 전화번호
- 인증번호 불일치
- 인증번호 만료
- 검증 시도 횟수 초과
- 너무 빠른 재발송 요청
- 문자 발송 서비스 오류

## 8. 상태 변화

```text
UNVERIFIED
-> CODE_SENT
-> VERIFIED
-> CONSUMED
```

실패 상태:

- `EXPIRED`
- `BLOCKED`

## 9. 만료 정책

- 인증번호 유효 시간: 3분
- 인증 완료 상태 유효 시간: 10분
- 재발송 대기 시간: 30초
- 인증번호 최대 검증 횟수: 구현 시 상수로 고정한다.

## 10. Redis key

```text
phone:code:{phone}:{purpose}
phone:verified:{phone}:{purpose}
phone:cooldown:{phone}:{purpose}
phone:reservation:{phone}:{purpose}
```

## 11. 관련 API

- `POST /api/auth/phone/send`
- `POST /api/auth/phone/verify`
- `GET /api/auth/phone/status`
- `DELETE /api/auth/phone/status`

## 12. 클라이언트 처리

- 인증 성공 시 전화번호 입력 비활성화
- 인증번호 입력 비활성화
- 발송 및 인증 버튼 비활성화
- 인증 완료 메시지 표시
- 인증 만료 시 다시 입력할 수 있도록 변경

## 13. 보안

- 인증번호를 로그에 출력하지 않는다.
- Redis에 인증번호 평문을 저장하지 않는다.
- `attemptCount`로 인증번호 대입 공격을 제한한다.
- 전화번호별 재발송 cooldown을 적용한다.
- 인증 완료 정보는 목적별 성공 처리 시 한 번만 소비한다.

## 14. 미결정 사항

- 실제 SMS 공급자 최종 선택
