# E. 채팅 및 알림

## 1. 목적

사용자가 판매자와 구매자 사이에서 실시간으로 대화하고, 채팅/경매/거래/후기 이벤트를 알림으로 받을 수 있게 한다.

## 2. 액터

- 구매자
- 판매자
- 입찰자
- 낙찰자
- 관리자
- Socket.IO 서버

## 3. 채팅 기능

- 상품별 채팅방 생성
- 채팅방 목록 조회
- 채팅 메시지 전송
- 이미지 메시지 전송
- 시스템 메시지 표시
- 송금 요청 메시지
- 거래 완료 메시지
- 비활성 사용자 포함 채팅방 읽기 전용 표시

## 4. 알림 기능

- 새 채팅방 알림
- 새 메시지 알림
- 새 입찰 알림
- 최고가 갱신으로 밀려난 알림
- 낙찰 알림
- 경매 종료/유찰 알림
- 게시글 삭제 알림
- 결제/송금 완료 알림
- 새 후기 알림

## 5. Socket.IO 정책

- Socket은 경매, 채팅, 알림에만 사용한다.
- 사용자는 로그인 후 Socket 연결을 맺는다.
- Socket 연결 시 access token 또는 별도 인증 정보를 검증한다.
- 사용자는 채팅방 입장 시 `chat:{chatRoomIdx}` room에 join한다.
- 사용자는 경매 상세 입장 시 `auction:{listingIdx}` room에 join한다.
- 채팅 텍스트 메시지는 Socket command로 전송한다.
- 채팅 이미지 메시지는 채팅 이미지 업로드 API로 저장한 뒤 Socket 이벤트로 전파한다.
- 중요한 상태 변경은 Service/DB 처리 후 Socket 이벤트를 보낸다.

## 6. 알림 저장 정책

- 일반 알림은 DB `notifications`에 먼저 저장한다.
- 접속 중 사용자는 Socket으로 즉시 수신한다.
- 미접속 사용자는 다음 접속 또는 알림 조회에서 `is_read=false`로 확인한다.
- NEW_MESSAGE 알림은 수신자가 해당 채팅방을 보고 있지 않을 때만 메시지 단위로 DB에 저장한다.
- 수신자가 해당 채팅방을 보고 있으면 NEW_MESSAGE 알림 row를 만들지 않는다.
- 알림 목록은 채팅방별 집계가 가능해야 한다.
- 사용자가 현재 보고 있는 채팅방의 메시지는 `chat:read`로 마지막 읽은 메시지 기준 읽음 처리한다.

## 7. 읽기 전용 채팅방

- 상대방이 탈퇴 또는 영구정지된 경우 기존 채팅방과 메시지는 보존한다.
- 상대방 표시는 `삭제된 사용자`로 통일한다.
- 프로필 이미지와 프로필 이동은 비활성화한다.
- 신규 텍스트 메시지, 이미지 메시지, 송금 요청을 차단한다.
- 삭제된 게시글 또는 삭제된 경매의 기존 채팅방도 읽기 전용으로 유지한다.
- 읽기 전용 채팅방에서도 과거 메시지 조회는 가능하다.

## 8. 예외 플로우

- 정지 사용자의 채팅 전송
- 존재하지 않는 채팅방
- 채팅방 참여자가 아닌 사용자의 접근
- 종료된 경매에서 새 채팅 또는 입찰 이벤트
- 삭제된 게시글의 채팅 접근
- 비활성 사용자 포함 채팅방의 신규 메시지/이미지/송금 요청
- Socket 인증 실패
