# B-02 관심목록 추가·해제

## 요청 계약

- 추가: 타입별 상세 API의 `POST .../:listingIdx/favorite`
- 해제: `DELETE .../:listingIdx/favorite`
- body 없음, 인증 쿠키 필수

## Frontend 순서

1. `canFavorite`가 false면 로그인 또는 비허용 상태를 안내한다.
2. 클릭 후 낙관적으로 표시할 수 있지만 같은 listing 요청은 직렬화한다.
3. 성공 응답의 `favorited`, `favoriteCount`로 최종 보정한다.
4. 실패하면 이전 상태로 되돌린다.

## Backend 추가 순서

1. 인증·활성 사용자와 listing id를 검증한다.
2. DB에서 `deleted_at IS NULL`인 listing을 조회한다.
3. 종료 경매도 관심 추가를 허용한다.
4. `(user_idx, listing_idx)`가 이미 있으면 현재 상태를 성공으로 반환하는 idempotent 방식으로 처리한다.
5. 없으면 `favorites`를 insert하고 commit한다.
6. commit된 count를 응답한다.

## Backend 해제 순서

1. 인증 사용자 소유의 favorite만 조건부 delete한다.
2. 이미 없더라도 `favorited=false` 성공으로 처리한다.
3. 현재 count를 응답한다.

## 동시성과 삭제

- DB UNIQUE `(user_idx, listing_idx)`가 중복 추가를 막는다.
- 게시글 삭제 transaction은 관련 favorites를 제거한다.
- 추가와 삭제가 겹치면 listing 삭제 조건을 다시 확인하거나 FK/row lock 정책으로 삭제 후 favorite가 남지 않게 한다.
- Redis와 Socket은 사용하지 않는다.
