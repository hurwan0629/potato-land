# D-01 경매글 등록·수정

## 목적

경매의 영속 원본을 DB에 생성·수정하고 종료 Timer를 연결한다. 삭제는 중복 설명을 피하기 위해 [[D-05 경매 삭제]]를 따른다.

## 요청 계약

| 동작 | 요청 | 형식 |
|---|---|---|
| 등록 | `POST /api/auctions` | `multipart/form-data` |
| 수정 | `PATCH /api/auctions/:listingIdx` | `multipart/form-data` |
| 삭제 | `DELETE /api/auctions/:listingIdx` | JSON, D-05 참조 |

등록 form은 `title`, `description`, `categoryIdx`, `productStatus`, `startPrice`, `preferredTradeLocation`, `images[]`를 보낸다. 수정 form에서는 `startPrice`를 제외한다. `startedAt`, `endsAt`, `status`, `currentPrice`, `bidUnit`은 클라이언트가 보내지 않고 서버가 결정한다.

## Frontend 구현 흐름

1. 필수값, 상품 상태, 양수 시작가, 이미지 개수(최대 4장)·형식을 먼저 검증한다.
2. 제출 중 버튼을 잠가 같은 form이 중복 전송되지 않게 한다.
3. `credentials: "include"`로 multipart 요청을 보낸다.
4. `201`이면 응답의 `listingIdx`로 상세 화면에 이동한다.
5. `VALIDATION_ERROR`는 필드에 표시하고 `UPLOAD_FAILED`는 form 값을 유지한 채 재시도를 제공한다.
6. 수정 화면은 상세 응답으로 초기화하며 `ON_GOING`이 아니면 저장 버튼을 비활성화한다.

## Backend 등록 실행 순서

1. Access Token을 검증하고 DB에서 활성 사용자를 조회한다.
2. multipart 필드와 파일의 MIME, 크기, 개수를 검증한다.
3. `categoryIdx`가 유효한지 DB에서 확인한다.
4. 업로드 파일을 storage service로 저장하고 공개 URL 목록을 만든다.
5. DB transaction을 시작한다.
6. `listings`에 작성자, `AUCTION`, 제목·설명·상품 상태·희망 거래 위치를 저장한다.
7. `auction_posts`에 `ON_GOING`, 시작가와 동일한 현재가, 서버 시각의 `started_at`, 24시간 뒤 `ends_at`을 저장한다.
8. `post_images`를 정렬 순서와 함께 저장한다.
9. commit 후 `ends_at` 기준 Timer를 `auctionTimers`에 등록한다.
10. 생성된 상태를 `201`로 응답한다. 최초 입찰 전에는 Redis 경매 state를 만들지 않아도 된다.

DB rollback이면 새로 저장한 파일을 best-effort로 정리한다. 파일 정리 재시도 작업은 storage service 확장 지점으로 남긴다.

## Backend 수정 실행 순서

1. 인증·활성 사용자와 `listingIdx` 형식을 검증한다.
2. `listings`와 `auction_posts`를 함께 조회하고 삭제 글은 `404`로 숨긴다.
3. 판매자 본인인지 확인한다. 관리자 삭제는 가능하지만 일반 수정 권한으로 사용하지 않는다.
4. DB `status === ON_GOING` 및 현재 시각이 `ends_at` 이전인지 확인한다.
5. 수정 허용 필드를 제목·설명·카테고리·상품 상태·희망 거래 위치·이미지로 제한한다.
6. `startPrice`, `currentPrice`, `bidUnit`, `startedAt`, `endsAt`이 요청에 있으면 거부한다.
7. 새 파일이 있을 때 먼저 검증·저장한다.
8. transaction에서 허용 필드와 이미지 row를 변경한다.
9. commit 후 교체된 기존 파일을 best-effort로 정리한다.
10. 설명 필드 변경은 Redis 경매 state와 무관하므로 Redis를 갱신하지 않는다.

## 분기와 응답

| 조건 | 결과 |
|---|---|
| 미인증/비활성 사용자 | `401 UNAUTHORIZED` / `403 BANNED_USER` |
| 잘못된 필드·파일 | `400 VALIDATION_ERROR` / `UPLOAD_FAILED` |
| 삭제 또는 존재하지 않음 | `404 NOT_FOUND` |
| 판매자 아님 | `403 FORBIDDEN` |
| 종료됨 | `409 AUCTION_CLOSED` |
| 경매 조건 변경 시도 | `400 IMMUTABLE_FIELD` |

## 저장소와 동기화

- DB 변경: `listings`, `auction_posts`, `post_images`
- Redis: 등록·일반 수정에서는 사용하지 않는다.
- Timer: 등록 commit 후 생성한다. Timer 등록 실패 시 DB `ends_at`은 유지되며 Recovery Scheduler가 복구한다.
- Socket: 등록·수정 성공 자체는 실시간 이벤트를 보내지 않는다.

## 무결성 체크

- [ ] 등록 endpoint는 `POST /api/auctions`
- [ ] 종료 시각은 서버가 DB에 저장
- [ ] DB commit 전 Timer 등록 금지
- [ ] 생성 후 시작가와 경매 조건 수정 금지
- [ ] Redis에 제목·설명·종료 시각을 중복 저장하지 않음
