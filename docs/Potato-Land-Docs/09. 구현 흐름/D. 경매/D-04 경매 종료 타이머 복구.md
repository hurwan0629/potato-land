# D-04 경매 종료 타이머 복구

## 목적

경매 생성 후 24시간이 지나면 서버가 경매를 종료하고, 서버 재시작 시 누락된 Timer를 복구한다.

## Frontend 구현 흐름

- 카운트다운은 서버 응답의 `endsAt`을 기준으로 표시한다.
- 실제 종료 처리는 프론트에서 하지 않는다.
- `auction:ended` 수신 시 입찰/채팅 버튼을 비활성화한다.
- 낙찰자에게는 송금/채팅 안내 UI를 표시한다.

## Backend 구현 흐름

- 경매 생성 시 DB `auction_posts.ends_at`을 저장한다.
- 서버 메모리 `auctionTimers`에는 `listingIdx`, `timeoutId`만 저장한다.
- Timer 실행 시 DB에서 해당 경매를 다시 조회한다.
- `deleted_at IS NOT NULL`이면 종료 처리하지 않는다.
- `status !== ON_GOING`이면 종료 처리하지 않는다.
- Redis `auction:state:{listingIdx}`와 DB 입찰 이력을 기준으로 낙찰 여부를 확정한다.
- 낙찰자가 있으면 `auction_posts.status = FINISHED`, `winning_bid_idx`를 저장한다.
- 낙찰자가 없으면 `FINISHED`로 종료하고 유찰 알림을 저장한다.
- 종료 후 `auction:state:{listingIdx}`를 삭제한다.
- `auctionTimers`에서 제거한다.
- `auction:ended`, `auction:won`, 관련 알림을 전송한다.

## Recovery Scheduler

- 서버 시작 시 `auction_posts.status = ON_GOING`이고 `listings.deleted_at IS NULL`인 경매를 조회한다.
- `ends_at`이 미래면 남은 시간으로 Timer를 복원한다.
- `ends_at`이 지났으면 즉시 종료 처리한다.
- 삭제된 경매는 복구 대상에서 제외한다.

## Redis 확인/변경

- 조회/삭제: `auction:state:{listingIdx}`

## 구현 체크리스트

- [ ] 프론트 종료 처리 금지
- [ ] DB `ends_at`이 종료 기준

- [ ] Redis `endsAt` 저장 안 함
