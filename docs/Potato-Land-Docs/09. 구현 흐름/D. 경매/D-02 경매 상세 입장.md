# D-02 경매 상세 입장

## 목적

사용자가 경매 상세 화면에 진입하고 실시간 경매 room에 참여한다.

## Frontend 구현 흐름

- 상세 API를 먼저 호출한다.
- 404면 삭제 또는 존재하지 않는 경매로 처리한다.
- 응답의 `canBid`, `canChat`, `canFavorite`로 버튼 상태를 결정한다.
- 진행 중 경매면 Socket 연결 후 `auction:join`을 호출한다.
- 종료된 경매는 조회 가능하지만 입찰/채팅은 비활성화한다.
- `auction:bid-updated`, `auction:leader-changed`, `auction:ended`, `auction:deleted`를 수신해 UI를 갱신한다.
- 화면 이탈 시 `auction:leave`를 호출한다.

## Backend 구현 흐름

- HTTP 상세 조회는 로그인 optional로 처리한다.
- 로그인 사용자가 있으면 사용자 활성 상태를 확인한다.
- `listings.deleted_at IS NULL`을 확인한다.
- DB `auction_posts.status`, `start_price`, `ends_at`을 조회한다.
- Redis `auction:state:{listingIdx}`가 있으면 현재가 필드는 Redis 값을 우선 사용한다.
- Redis state가 없으면 DB `current_price`, `winning_bid_idx` 기준으로 응답한다.
- Socket `auction:join`은 access token과 사용자 활성 상태를 필수로 확인한다.
- 삭제된 경매는 join을 차단한다.
- 종료된 경매는 join 가능하지만 입찰/채팅 불가 상태로 응답한다.
- join 성공 시 `socket.data.activeAuctionListingIdx = listingIdx`로 갱신한다.

## DB 확인/변경

- 조회: `listings`, `auction_posts`, `auction_bids`, `users`, `favorites`

## Redis 확인/변경

- 조회: `auction:state:{listingIdx}`

## Socket

- Client -> Server: `auction:join`, `auction:leave`
- Server -> Client: 경매 상태 변경 이벤트
