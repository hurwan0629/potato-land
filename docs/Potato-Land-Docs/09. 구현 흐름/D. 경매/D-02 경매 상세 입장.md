# D-02 경매 상세 조회·Room 입장

## 목적

HTTP로 영속 상태를 먼저 조회하고, 진행 중 실시간 변경만 Socket room에서 받는다.

## 요청 계약

- 상세: `GET /api/auctions/:listingIdx` (로그인 optional)
- Room 입장: `auction:join { listingIdx }` (로그인 필수)
- Room 퇴장: `auction:leave { listingIdx }`

## Frontend 구현 흐름

1. 상세 API를 먼저 호출한다. Socket 이벤트만으로 초기 화면을 만들지 않는다.
2. 응답의 `status`, `canBid`, `canChat`, `canFavorite`, `endsAt`으로 버튼과 카운트다운을 구성한다.
3. `ON_GOING`이고 로그인 상태면 Socket 연결 후 `auction:join`을 보낸다.
4. ack의 상태가 HTTP 응답보다 새로우면 현재가를 갱신한다.
5. `auction:bid-updated`는 더 큰 `bidIdx`일 때만 반영한다.
6. `auction:leader-changed`, `auction:ended`, `auction:deleted`를 받으면 동작 버튼을 즉시 잠그고 필요하면 상세 API를 재조회한다.
7. 화면 이탈 시 `auction:leave`를 보내고 리스너를 제거한다.

종료 경매의 일반 채팅 버튼은 비활성화한다. 판매자·낙찰자에게 이미 정산 거래가 있다면 경매 상세의 일반 채팅 버튼이 아니라 거래/채팅 내역 링크를 사용한다.

## Backend 상세 조회 순서

1. `listingIdx`를 양의 정수로 검증한다.
2. optional access token이 있으면 검증하고 DB 사용자 상태를 확인한다. 잘못된 토큰을 익명으로 무시하지 않는다.
3. `listings`, `auction_posts`, 판매자, 이미지, 관심 여부를 조회한다.
4. `deleted_at IS NOT NULL`이면 존재하지 않는 것처럼 `404`를 반환한다.
5. DB의 `status`, `start_price`, `ends_at`, `winning_bid_idx`를 영속 기준으로 삼는다.
6. `ON_GOING`이면 Redis Hash를 조회한다.
7. Redis state가 있으면 `currentPrice`, `highestBidderIdx`, `highestBidIdx`만 덮어쓴다.
8. Redis miss이면 DB 현재가로 응답한다. 상세 조회를 위해 Redis state를 반드시 생성하지 않는다.
9. `minNextBid`는 선택된 현재가로 서버가 계산한다.
10. DB 상태와 사용자 관계로 권한 필드를 계산해 응답한다.

## 권한 필드

| 필드 | true 조건 |
|---|---|
| `canBid` | 활성 로그인 사용자, `ON_GOING`, 종료 전, 판매자 아님 |
| `canChat` | 활성 로그인 사용자, `ON_GOING`, 판매자 아님 |
| `canFavorite` | 활성 로그인 사용자, 삭제되지 않음. `FINISHED`도 가능 |
| `canCreateSettlement` | 판매자, `FINISHED`, 유효 낙찰자 존재, 활성 `REQUESTED` 거래 없음 |

## Socket `auction:join` 순서

1. 연결 시 검증한 `socket.data.user`가 활성 상태인지 확인한다.
2. DB에서 경매와 `deleted_at`을 확인한다.
3. Socket.IO room `auction:{listingIdx}`에 join한다.
4. `socket.data.activeAuctionListingIdx`를 갱신한다.
5. DB 상태와 선택적 Redis 현재가를 포함한 ack를 보낸다.

종료 경매 room 입장은 과거 상태 확인을 위해 허용할 수 있지만 입찰 요청은 항상 HTTP에서 다시 거부한다.

## 저장소와 장애 분기

- DB 조회: `listings`, `auction_posts`, `auction_bids`, `users`, `post_images`, `favorites`, 선택적 `transactions`
- Redis 조회: 진행 중일 때 `auction:state:{listingIdx}`만 optional
- Redis 장애: DB 값으로 상세를 표시할 수 있지만 `canBid=false`와 일시적 제한 사유를 내려 신규 입찰을 막는다.
- Socket 단절: 화면은 마지막 HTTP 상태를 유지하고 재연결 후 상세 API를 다시 호출한다.
