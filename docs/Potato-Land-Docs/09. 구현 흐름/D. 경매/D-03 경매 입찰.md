# D-03 경매 입찰

## 목적

진행 중 경매에서 입찰가를 검증하고 Redis와 DB에 반영한 뒤 실시간 이벤트를 전송한다.

## 관련 API/Socket

- `POST /api/auctions/:listingIdx/bids`
- `auction:bid-updated`
- `auction:outbid`

## Frontend 구현 흐름

- 로그인 사용자만 입찰 버튼을 사용할 수 있다.
- 입력값이 숫자인지, 현재 `minNextBid` 이상인지 1차 검증한다.
- 요청 중에는 입찰 버튼을 잠근다.
- 성공 응답 또는 `auction:bid-updated` 이벤트로 현재가와 최소 다음 입찰가를 갱신한다.
- `BID_TOO_LOW`, `AUCTION_CLOSED`, `REDIS_UNAVAILABLE`, `INACTIVE_USER`를 code별로 표시한다.

## Backend 구현 흐름

- access token과 사용자 활성 상태를 확인한다.
- 경매 존재와 `listings.deleted_at IS NULL`을 확인한다.
- DB `auction_posts.status === ON_GOING`을 확인한다.
- 현재 시간이 `ends_at` 이전인지 확인한다.
- 판매자 본인 입찰을 차단한다.
- Redis 사용 가능 여부를 확인한다. Redis 장애 시 신규 입찰은 차단한다.
- `auction:state:{listingIdx}`가 없으면 DB 기준으로 초기 state를 만든다.
- Redis 원자 처리로 `bidAmount >= minNextBid`를 검증하고 최고 입찰 상태를 갱신한다.
- DB transaction을 시작한다.
- `auction_bids`를 insert한다.
- `auction_posts.current_price`, `winning_bid_idx`를 갱신한다.
- DB commit 후 `auction:bid-updated`를 경매방에 전송한다.
- 이전 최고 입찰자가 있으면 `OUTBID` 알림을 저장하고 `auction:outbid` 또는 `notification:new`을 전송한다.
- DB 저장 실패 시 Redis state를 DB 기준으로 복구하고 실패 응답을 반환한다.

## DB 확인/변경

- 조회: `listings`, `auction_posts`, `users`
- 변경: `auction_bids`, `auction_posts`, `notifications`

```text
auction:state:{listingIdx}
```
