# D-06 최고 입찰자 재계산

## 목적

최고 입찰자가 탈퇴 또는 영구정지되면 DB 이력을 보존한 채 다음 유효 입찰자를 최고 입찰자로 확정한다.

## 호출 시점

- 사용자 자진 탈퇴 공통 서비스
- 관리자 영구정지 공통 서비스
- 호출자는 비활성화 대상 `userIdx`를 넘기고, 이 서비스는 해당 사용자가 현재 최고 입찰자인 진행 경매만 처리한다.

## Backend 실행 순서

경매별로 다음을 수행한다.

1. DB transaction에서 `auction_posts` row를 잠근다.
2. 경매가 삭제되지 않았고 `ON_GOING`, 종료 전인지 다시 확인한다.
3. `auction_bids`를 `bid_amount DESC, created_at ASC, idx ASC`로 조회한다.
4. 탈퇴·정지되지 않은 입찰자의 첫 bid를 후보로 선택한다.
5. 후보가 있으면 `winning_bid_idx`, `current_price`를 후보로 갱신한다.
6. 후보가 없으면 `winning_bid_idx = NULL`, `current_price = start_price`로 복원한다.
7. 후보에게 `AUCTION_LEADER_CHANGED` 알림을 저장한다.
8. commit한다.
9. Redis Hash의 세 입찰 필드를 DB 결과로 덮어쓴다.
10. 경매 room에 `auction:leader-changed`, 후보 개인 room에 알림을 전송한다.

기존 입찰 row에는 유효/무효 표시를 추가하지 않고 그대로 보존한다. 유효성은 입찰자 `users.deleted_at`, `banned_at`으로 판단한다.

## Frontend 처리

1. 이벤트를 받으면 현재가와 최고 입찰자 표시를 바꾼다.
2. 내부 탈퇴·제재 원인을 보여주지 않는다.
3. 개인 알림은 서버가 준 일반 문구를 사용한다.
4. 현재 화면과 이벤트가 충돌하면 상세 API를 재조회한다.

## 실패 분기

- DB 실패: Redis와 Socket을 변경하지 않고 사용자 비활성화 transaction 정책에 따라 전체 또는 해당 경매 처리를 실패시킨다.
- commit 후 Redis 실패: DB 결과가 최종이며 다음 상세/입찰 초기화 시 복원한다. 입찰은 Redis 회복 전 차단할 수 있다.
- commit 후 Socket 실패: HTTP 재조회로 회복한다.
- 경매가 이미 종료/삭제됨: 재계산 없이 넘어간다.

## 저장소 책임

- DB 조회/변경: `auction_posts`, `auction_bids`, `users`, `notifications`
- Redis: `auction:state:{listingIdx}` 세 필드 갱신
- Socket: 확정 결과만 전파
