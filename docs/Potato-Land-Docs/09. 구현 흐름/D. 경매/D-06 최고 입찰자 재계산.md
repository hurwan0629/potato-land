# D-06 최고 입찰자 재계산

## 목적

현재 최고 입찰자가 탈퇴 또는 영구정지되었을 때 다음 유효 입찰자를 최고 입찰자로 승격한다.

## Frontend 구현 흐름

- `auction:leader-changed`를 수신하면 현재가, 최소 다음 입찰가, 최고 입찰자 표시를 갱신한다.
- 내부 제재 사유는 표시하지 않는다.
- 메시지는 서버 payload의 `message`를 그대로 사용한다.

## Backend 구현 흐름

- 사용자 비활성화 처리 중 해당 사용자가 최고 입찰자인 진행 중 경매를 조회한다.
- 각 경매에서 `auction_bids`를 금액/시간 기준으로 정렬해 다음 유효 입찰자를 찾는다.
- 유효 조건은 입찰자가 탈퇴/정지되지 않은 사용자다.
- 후보가 있으면 `auction_posts.current_price`, `winning_bid_idx`를 후보 bid로 갱신한다.
- 후보가 없으면 `winning_bid_idx = NULL`, `current_price = start_price`로 복원한다.
- DB commit 후 Redis `auction:state:{listingIdx}`를 DB 결과로 갱신한다.
- 경매방에 `auction:leader-changed`를 전송한다.
- 후보가 있으면 `AUCTION_LEADER_CHANGED` 알림을 저장/전송한다.
- 후보가 없으면 개인 알림 없이 경매방 상태 변경 이벤트만 전송한다.

## DB 확인/변경

- `notifications`
