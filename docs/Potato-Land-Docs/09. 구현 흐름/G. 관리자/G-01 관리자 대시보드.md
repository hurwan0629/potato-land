# G-01 관리자 대시보드

## 요청과 Frontend

- 관리자 통계 API에 `from`, `to`, 선택적 `interval=HOUR|DAY`를 query로 보낸다.
- 날짜는 브라우저 timezone 표시와 서버 집계 timezone을 구분한다.
- 차트는 서버 aggregate를 그대로 표시하고 실시간 Socket 통계는 MVP에서 만들지 않는다.

## Backend 순서

1. Access Token과 DB의 현재 `ADMIN` role, 활성 상태를 확인한다.
2. 날짜 형식, 최대 범위, from <= to를 검증한다.
3. 탈퇴·정지되지 않은 회원 수, 전체 게시글 수, 완료 거래 수, 완료 거래 금액을 집계한다.
4. 범위 내 게시글 등록 추이와 완료 거래 추이를 `interval` 기준 bucket으로 집계한다.
5. 상태별 count는 문서의 공통 enum만 사용한다.
6. bucket이 없는 구간은 API DTO에서 0으로 채운다.
7. 동일 기준 시각으로 집계한 결과를 응답한다.

## 저장소와 복잡도 기준

- PostgreSQL aggregate만 사용하며 Redis 통계 캐시는 만들지 않는다.
- 트래픽이 실제 문제가 될 때 materialized view나 배치 집계를 확장한다.
- 관리자 대시보드 때문에 거래·알림 서비스에 별도 실시간 쓰기를 추가하지 않는다.
