# G-02 사용자 영구정지

## 목적

관리자가 사용자를 실제 삭제하지 않고 영구정지 처리하며 관련 진행 중 상태를 정리한다.

## Frontend 구현 흐름

- 관리자 상세 화면에서 영구정지 버튼을 제공한다.
- 성공 시 사용자 상태를 `BANNED`로 갱신한다.
- 대상 사용자의 공개 화면에서는 `삭제된 사용자` 표시 정책이 적용된다.

## Backend 구현 흐름

- access token과 관리자 권한을 확인한다.
- 대상 사용자가 이미 비활성인지 확인한다.
- DB transaction을 시작한다.
- `users.banned_at`을 저장하고 `banned_until`은 null로 둔다.
- 대상 사용자의 `REQUESTED` 거래를 `CANCELED`로 변경한다.
- 대상 사용자가 소유한 진행 중 경매를 soft delete한다.
- 대상 사용자가 최고 입찰자인 진행 중 경매를 재계산한다.
- DB commit 후 대상 사용자의 refresh session을 삭제한다.
- 관련 `auction:state:{listingIdx}`를 삭제 또는 갱신한다.
- 관련 Timer를 제거한다.
- 대상 사용자 Socket 연결을 강제 종료한다.
- 경매 삭제/최고입찰자 변경 알림과 Socket 이벤트를 전송한다.

## DB 확인/변경

- `users`
- `transactions`
- `listings`
- `auction_posts`
- `auction_bids`
- `notifications`

## Redis 확인/변경

- 삭제: `session:{sub}:*`
- 삭제/갱신: `auction:state:{listingIdx}`

## Socket

- 대상 사용자 disconnect
- `auction:deleted`
- `auction:leader-changed`
- `notification:new`

## 구현 체크리스트

- [ ] row 삭제 금지
- [ ] 영구정지는 `banned_at`, `banned_until = null`
- [ ] REQUESTED 거래 CANCELED
- [ ] 소유 진행 중 경매 soft delete
- [ ] 최고 입찰자 재계산
