# G-02 사용자 영구정지

## Frontend 순서

1. 관리자 상세에서 대상 사용자와 영향을 확인하는 모달을 표시한다.
2. 요청 중 버튼을 잠근다.
3. 성공하면 사용자 상태와 관련 목록을 재조회한다.
4. 대상의 공개 화면은 `삭제된 사용자` 표시 정책을 따른다.

## Backend transaction 순서

1. 요청자의 access와 DB 현재 관리자 권한을 확인한다.
2. 대상 사용자 row를 잠그고 자기 자신 또는 정책상 금지된 관리자를 차단한다.
3. 이미 정지/탈퇴한 대상은 현재 상태에 맞는 idempotent 응답 또는 `409`로 통일한다.
4. `banned_at=now`, `banned_until=NULL`을 저장한다.
5. 대상이 포함된 모든 `REQUESTED` 거래를 `CANCELED`로 바꾸고 활성 상대에게만 일반 `PAYMENT_CANCELED` 알림을 저장한다. REQUESTED가 없으면 거래 알림을 만들지 않는다.
6. 대상이 소유한 판매 중 중고글과 진행 경매를 soft delete하고 favorites를 제거한다. 경매는 D-05와 같은 규칙을 적용한다.
7. 대상이 최고 입찰자인 다른 진행 경매를 D-06 규칙으로 재계산한다.
8. commit한다.

## commit 후 정리

1. `session:{sub}:*`를 삭제한다.
2. 삭제 경매 Redis/Timer를 제거한다.
3. 재계산 경매 Redis를 DB 결과로 갱신한다.
4. 경매·알림 Socket 이벤트를 보낸다.
5. 대상 사용자의 모든 Socket 연결을 종료한다.

DB transaction 실패 시 위 외부 상태를 변경하지 않는다. commit 후 일부 정리가 실패하면 정지 상태는 유지하고 재시도 지점을 로그로 남긴다.
