# A-03 로그인 토큰 재발급 로그아웃

## 목적

쿠키 기반 Access/Refresh Token과 Redis session으로 로그인 상태를 관리한다.

## 관련 API

- `POST /api/auth/login`
- `POST /api/auth/refresh`
- `POST /api/auth/logout`

## Frontend 구현 흐름

- 로그인 성공 후 별도 토큰 저장 없이 쿠키 인증을 사용한다.
- 모든 보호 API는 `credentials: "include"` 또는 `withCredentials: true`로 호출한다.
- 401 발생 시 `POST /api/auth/refresh` 호출 후 원래 요청을 재시도한다.
- refresh 실패 시 로그인 화면으로 이동한다.
- 로그아웃 시 `POST /api/auth/logout`을 호출하고 클라이언트 상태를 비운다.

## Backend 구현 흐름

- 로그인 시 loginId/password를 검증한다.
- 사용자 `deleted_at`, `banned_at`이 있으면 로그인 차단한다.
- `sid`, access `jti`, refresh `jti`를 생성한다.
- Redis `session:{sub}:{sid}`에 현재 refresh `jti`를 저장하고 TTL 7일을 설정한다.
- access cookie path는 `/`, refresh cookie path는 `/api/auth/refresh`로 설정한다.
- refresh API는 refresh JWT `type`, `sid`, `jti`와 Redis `currentRefreshJti`를 비교한다.
- 일치하면 access/refresh를 재발급하고 Redis `currentRefreshJti`를 새 refresh `jti`로 교체한다.
- 불일치하면 refresh token 재사용으로 보고 해당 session key를 삭제한다.
- 로그아웃은 가능한 경우 session key를 삭제하고 두 쿠키를 Max-Age 0으로 내려준다.

## Redis 확인/변경

```text
session:{sub}:{sid}
```

## 예외 조건

- `INVALID_CREDENTIALS`
- `BANNED_USER`
- `DELETED_USER`
- `REFRESH_TOKEN_INVALID`

## 구현 체크리스트

- [ ] access claim에 `role` 포함
- [ ] refresh claim에 `role` 미포함
- [ ] refresh cookie Path `/api/auth/refresh`
- [ ] refresh rotation 시 Redis jti 비교
