# A-01 전화번호 인증

## 목적

회원가입, 아이디 찾기, 비밀번호 재설정, 전화번호 변경에서 전화번호 소유 여부를 확인한다.

## 관련 API

- `POST /api/auth/phone/send`
- `POST /api/auth/phone/verify`
- `GET /api/auth/phone/status`
- `DELETE /api/auth/phone/status`

## Frontend 구현 흐름

- 사용자가 `phone`, `purpose`를 입력하거나 화면 목적에 따라 `purpose`를 고정한다.
- 인증번호 발송 버튼 클릭 시 `POST /api/auth/phone/send`를 호출한다.
- 성공하면 `expiresInSeconds`, `resendAfterSeconds`로 타이머와 재발송 버튼 상태를 표시한다.
- 인증번호 입력 후 `POST /api/auth/phone/verify`에 `phone`, `purpose`, `code`를 보낸다.
- 인증 성공 후 다음 단계 API에는 `phone`을 그대로 보낸다.
- `phoneVerificationId`는 사용하지 않는다.

## Backend 구현 흐름

- `phone` 형식과 `purpose` enum을 검증한다.
- `phone:cooldown:{phone}:{purpose}`가 있으면 `TOO_MANY_REQUESTS`를 반환한다.
- `SIGNUP`, `CHANGE_PHONE` 목적이면 기존 사용자 전화번호와 충돌하는지 확인한다.
- 6자리 인증번호를 생성하고 원문은 저장하지 않는다.
- Redis `phone:code:{phone}:{purpose}`에 `codeHash`, `attemptCount`, `expiresAt`을 저장한다.
- Redis `phone:cooldown:{phone}:{purpose}`를 30초 TTL로 저장한다.
- SMS는 MVP에서 Console/Fake provider로 출력한다.
- 검증 요청 시 code key를 조회하고 입력값 hash를 비교한다.
- 실패 시 `attemptCount`를 증가시키고 허용 횟수를 넘으면 code key를 삭제한다.
- 성공 시 `phone:verified:{phone}:{purpose}`를 10분 TTL로 저장한다.
- `SIGNUP` 성공 검증 시 `phone:reservation:{phone}:SIGNUP`도 10분 TTL로 저장한다.

## Redis 확인/변경

```text
phone:code:{phone}:{purpose}
phone:verified:{phone}:{purpose}
phone:cooldown:{phone}:{purpose}
phone:reservation:{phone}:{purpose}
```

## 예외 조건

- `VALIDATION_ERROR`: phone, purpose, code 형식 오류
- `CONFLICT`: 이미 사용 중인 전화번호
- `TOO_MANY_REQUESTS`: 재발송 cooldown
- `PHONE_VERIFICATION_EXPIRED`: code key 없음 또는 만료
