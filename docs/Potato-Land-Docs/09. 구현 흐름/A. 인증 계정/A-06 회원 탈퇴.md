# A-06 회원 탈퇴

## 목적

사용자 row를 삭제하지 않고 계정을 비활성화하며 진행 중 상태를 정리한다. 관리자 영구정지와 같은 공통 비활성화 서비스를 사용한다.

## Frontend 순서

1. 탈퇴 영향 안내와 재확인 입력을 받는다.
2. 탈퇴 요청 중 버튼을 잠근다.
3. 성공하면 Socket을 끊고 사용자 캐시를 비우며 로그인 화면으로 이동한다.
4. 과거 거래·채팅·후기는 상대 화면에 `삭제된 사용자`로 남는다고 안내한다.

## Backend transaction 순서

1. 인증 사용자와 재확인 조건을 검증한다.
2. 사용자 row를 잠그고 이미 비활성인지 확인한다.
3. `users.deleted_at`을 기록한다.
4. 판매자가 가진 `REQUESTED`와 구매자인 `REQUESTED` 거래를 `CANCELED`로 바꾸고 상대에게 `PAYMENT_CANCELED` 알림을 저장한다.
5. 소유한 진행 중 경매를 soft delete하고 favorites·입찰자 알림을 처리한다.
6. 다른 진행 경매에서 최고 입찰자인 경우 D-06 기준으로 재계산한다.
7. 핵심 DB 변경을 commit한다.

## commit 후 정리

1. 사용자의 `session:{sub}:*` refresh session을 삭제한다.
2. 삭제 경매의 Redis state와 Timer를 정리한다.
3. 재계산 경매의 Redis state를 DB 결과로 갱신한다.
4. 관련 Socket 이벤트와 알림을 전송한다.
5. 사용자 Socket 연결을 강제 종료한다.

## 실패 원칙

- DB transaction 실패 시 Redis, Timer, Socket을 변경하지 않는다.
- commit 후 Redis/Socket 정리 실패는 탈퇴를 되돌리지 않고 재시도 로그를 남긴다.
- 기존 채팅, 입찰, 완료 거래, 후기 row는 삭제하지 않는다.
