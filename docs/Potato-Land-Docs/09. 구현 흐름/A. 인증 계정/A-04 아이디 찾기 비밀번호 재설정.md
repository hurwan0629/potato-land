# A-04 아이디 찾기·비밀번호 재설정

## 요청 계약

- 아이디 찾기: `POST /api/auth/find-id` `{ name, phone }`
- 비밀번호 재설정: `POST /api/auth/password/reset` `{ name, loginId, phone, newPassword, newPasswordConfirm }`

각 요청 전에 동일 phone으로 각각 `FIND_ID`, `RESET_PASSWORD` 인증을 완료한다.

## Frontend 공통 흐름

- 화면별 purpose를 고정하고 인증한 phone을 후속 요청에서도 그대로 사용한다.
- 제출 중 중복 요청을 막고 성공 후 인증 입력 상태를 비운다.

## Backend 공통 흐름

두 기능 모두 요청 형식, 목적별 verified key, DB 사용자 일치 조건을 순서대로 확인한다.

## 아이디 찾기 순서

1. 프론트가 인증 완료한 phone과 name을 제출한다.
2. 서버가 형식을 검증하고 `phone:verified:{phone}:FIND_ID`를 확인한다.
3. DB에서 `name + phone` 사용자를 조회한다.
4. 성공하면 verified key를 소비하고 마스킹 정책에 맞는 loginId를 응답한다.
5. 프론트는 응답을 화면에 표시한다. SMS로 아이디를 다시 보내지 않는다.

## 비밀번호 재설정 순서

1. 프론트가 새 비밀번호 일치·규칙을 검증해 제출한다.
2. 서버가 같은 규칙과 `phone:verified:{phone}:RESET_PASSWORD`를 확인한다.
3. DB에서 `name + loginId + phone` 사용자를 조회한다.
4. 정지·탈퇴 계정의 재설정 허용 여부는 인증 정책을 따르며 MVP에서는 차단한다.
5. 새 hash를 transaction으로 저장한다.
6. commit 후 verified key와 사용자의 모든 refresh session을 삭제한다.
7. 새 로그인 화면으로 이동시킨다.

## 실패 원칙

- purpose 또는 phone 불일치는 `VALIDATION_ERROR`다.
- 사용자 없음 응답은 계정 존재 정보가 과도하게 노출되지 않도록 문구를 통일한다.
- DB 실패 시 verified key를 소비하지 않는다.
- session 일괄 삭제 실패 시 새 비밀번호 저장 결과는 유지하되 보안 로그와 재시도 지점을 남긴다.
