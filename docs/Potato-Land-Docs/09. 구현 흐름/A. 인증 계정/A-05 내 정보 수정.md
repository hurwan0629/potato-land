# A-05 내 정보·프로필 수정

## 요청 경계

- 현재 비밀번호 확인: `POST /api/users/me/verify-password`
- 계정 정보 수정: 상세 API 명세의 `/api/users/me`
- 프로필 이미지/소개 수정: `PATCH /api/users/me/profile`
- 전화번호 변경 전 인증: purpose `CHANGE_PHONE`

## Frontend 순서

1. 수정 화면 진입 전에 현재 비밀번호를 확인한다.
2. 성공 응답의 짧은 TTL `verificationToken`을 메모리에만 둔다.
3. 실제로 바뀐 필드만 제출한다.
4. 새 비밀번호는 확인값과 함께 보내며 phone 변경은 새 phone의 `CHANGE_PHONE` 인증을 먼저 완료한다.
5. 성공하면 내 정보 API를 재조회하고 header/profile 캐시를 갱신한다.
6. 업로드 실패 시 기존 프로필 이미지를 유지한다.

## Backend 실행 순서

1. 인증·활성 사용자와 verificationToken의 사용자·용도·만료를 검증한다.
2. 변경 필드를 allowlist로 제한하고 형식을 검증한다.
3. nickname/email/phone 중복을 DB에서 확인한다.
4. phone 변경이면 `phone:verified:{newPhone}:CHANGE_PHONE`를 확인한다.
5. password 변경이면 새 password 일치·규칙을 확인해 hash한다.
6. 새 파일이 있으면 storage service에서 검증·저장한다.
7. transaction에서 사용자 필드와 프로필을 변경한다.
8. commit 후 verificationToken과 phone verified key를 소비한다.
9. 이미지가 바뀌었다면 commit 후 기존 파일을 best-effort로 정리한다.
10. password 변경 시 모든 refresh session을 폐기하고 현재 브라우저도 재로그인시킨다.

## 무결성 체크

- [ ] phone 변경 purpose 고정
- [ ] DB UNIQUE 최종 방어
- [ ] commit 후 임시 인증 상태 소비
