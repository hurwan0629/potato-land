# A-05 내 정보 수정

## 목적

내 정보 수정 전 비밀번호를 한 번 확인하고, 닉네임/이메일/전화번호/비밀번호를 변경한다.

## 관련 API

- `POST /api/users/me/verify-password`
- `PATCH /api/users/me`
- `PATCH /api/users/me/password`

## Frontend 구현 흐름

- 내 정보 수정 진입 시 바로 form을 보여주지 않고 비밀번호 확인 화면을 먼저 보여준다.
- 비밀번호 확인 성공 시 `verificationToken`을 임시 보관한다.
- 닉네임, 이메일 변경은 중복 검증 결과를 화면에 반영한다.
- 전화번호 변경은 `CHANGE_PHONE` 전화번호 인증을 먼저 완료한 뒤 `phone`을 보낸다.
- 비밀번호 변경은 `newPassword`, `newPasswordConfirm`을 보낸다.

## Backend 구현 흐름

- 비밀번호 확인 API는 access token 사용자와 password를 비교한다.
- 성공 시 짧은 TTL의 `verificationToken`을 발급한다.
- 정보 수정 API는 `verificationToken`을 검증한다.
- 닉네임/이메일 변경 시 중복을 DB에서 확인한다.
- 전화번호 변경 요청에 `phone`이 있으면 `phone:verified:{phone}:CHANGE_PHONE`을 확인한다.
- 변경 성공 시 전화번호 verified key를 소비한다.
- 비밀번호 변경 성공 시 기존 refresh session을 전부 삭제할지 정책을 확정한다. MVP에서는 현재 session 유지 가능.

## DB 확인/변경

- `users` password hash 조회
- `users.nickname`, `users.email`, `users.phone`, `users.password_hash` 변경

## Redis 확인/변경

- `phone:verified:{phone}:CHANGE_PHONE`

## 예외 조건

- `MEMBER_EDIT_VERIFICATION_REQUIRED`
- `INVALID_CREDENTIALS`
- `CONFLICT`
- `VALIDATION_ERROR`
