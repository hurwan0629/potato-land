# A-05 내 정보·프로필 수정

## 요청 경계

- 현재 비밀번호 확인: `POST /api/users/me/verify-password`
- 계정 정보 수정: 상세 API 명세의 `/api/users/me`
- 프로필 이미지/소개 수정: `PATCH /api/users/me/profile`
- 전화번호 변경 전 인증: purpose `CHANGE_PHONE`

## Frontend 순서

1. 수정 화면 진입 전에 현재 비밀번호를 확인한다.
2. 성공 응답의 짧은 TTL `verificationToken`을 메모리에만 둔다.
3. 실제로 바뀐 필드만 제출한다.
4. 새 비밀번호는 확인값과 함께 보내며 phone 변경은 새 phone의 `CHANGE_PHONE` 인증을 먼저 완료한다.
5. 성공하면 내 정보 API를 재조회하고 header/profile 캐시를 갱신한다.
6. 공개 프로필 수정 실패 시 기존 프로필 이미지와 소개글을 유지한다.

## Backend 실행 순서

1. 인증·활성 사용자와 verificationToken의 사용자·용도·만료를 검증한다.
2. 변경 필드를 allowlist로 제한하고 형식을 검증한다.
3. nickname/email/phone 중복을 DB에서 확인한다.
4. phone 변경이면 요청의 `phoneVerificationId`와 `phone:verified:{newPhone}:CHANGE_PHONE` value가 일치하는지 확인한다.
5. password 변경이면 새 password 일치·규칙을 확인해 hash한다.
6. transaction에서 요청에 포함된 계정 필드만 변경한다.
7. commit 후 verificationToken과 phone verified key를 소비한다.
8. password 변경 시 모든 refresh session을 폐기하고 현재 브라우저도 재로그인시킨다.

`PATCH /api/users/me/profile`은 위의 민감 정보 수정과 별개다. 현재 로그인만 확인하고
프로필 이미지와 소개글을 저장하며 `verificationToken`을 요구하지 않는다. 이미지 교체 시에는
새 파일과 DB 반영이 성공한 뒤 기존 파일을 best-effort로 정리한다.

## 무결성 체크

- [ ] phone 변경 purpose 고정
- [ ] DB UNIQUE 최종 방어
- [ ] commit 후 임시 인증 상태 소비
- [ ] 공개 프로필과 민감 회원 정보 수정 경계 분리
