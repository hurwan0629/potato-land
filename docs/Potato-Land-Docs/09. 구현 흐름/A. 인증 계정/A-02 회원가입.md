# A-02 회원가입

## 요청 계약

`POST /api/auth/signup`

body: `name`, `nickname`, `loginId`, `password`, `passwordConfirm`, `phone`, `phoneVerificationId`, 선택 `email`, `termsAgreed`.

화면의 이용약관·개인정보 동의 단일 체크박스는 `termsAgreed` 하나로 전송한다. `privacyAgreed`를 별도 필드로 두지 않는다.

## Frontend 순서

1. `SIGNUP` 전화번호 인증을 완료한 같은 phone을 제출한다.
2. 필수값·형식·비밀번호 확인·약관을 검증한다.
3. 제출 중 버튼을 잠근다.
4. 성공하면 토큰이 없음을 전제로 로그인 화면으로 이동한다.
5. 중복 오류는 `details.field`에 맞는 입력으로 이동한다.

## Backend 실행 순서

1. 모든 body 필드와 password 일치를 검증한다.
2. `phone:verified:{phone}:SIGNUP` 존재와 요청 `phoneVerificationId`의 일치를 확인한다.
3. DB에서 loginId, nickname, phone, email 중복을 사전 확인한다.
4. password를 hash한다.
5. transaction에서 `users`를 생성한다. DB UNIQUE 위반도 `409 CONFLICT`로 변환한다.
6. commit한다.
7. commit 성공 후 verified key를 삭제한다.
8. access/refresh token과 session key를 만들지 않고 `201`로 응답한다.

verified key 삭제 실패는 회원 row를 되돌리지 않는다. 같은 번호의 재가입은 DB UNIQUE가 막으며 key는 TTL로 만료된다.

## 저장소 책임

- DB: `users` 최종 중복과 영속 계정
- Redis: 전화번호 인증 완료 증명만 사용
- Socket: 사용하지 않는다.
