# A-02 회원가입

## 목적

전화번호 인증이 완료된 사용자 정보를 DB에 저장한다. 회원가입 성공 후 자동 로그인하지 않는다.

## 관련 API

- `POST /api/auth/signup`

## Frontend 구현 흐름

- 전화번호 인증 완료 후 회원가입 form을 제출한다.
- body에는 `name`, `nickname`, `loginId`, `password`, `passwordConfirm`, `phone`, `email`, 약관 동의 값을 보낸다.
- 성공하면 로그인 페이지로 이동하거나 로그인 form을 표시한다.
- 성공 응답에 토큰 쿠키가 없다는 점을 전제로 작업한다.

## Backend 구현 흐름

- body 필수값과 형식을 검증한다.
- `password`와 `passwordConfirm` 일치를 확인한다.
- `phone:verified:{phone}:SIGNUP`이 존재하는지 확인한다.
- `phone:reservation:{phone}:SIGNUP`이 존재하는지 확인한다.
- `loginId`, `nickname`, `phone`, `email` 중복을 DB에서 확인한다.
- DB transaction으로 사용자 row를 생성한다.
- 성공 후 `phone:verified:{phone}:SIGNUP`, `phone:reservation:{phone}:SIGNUP`을 삭제한다.
- access/refresh token은 발급하지 않는다.

## DB 확인/변경

- `users` 중복 조회
- `users` insert

## Redis 확인/변경

- 확인: `phone:verified:{phone}:SIGNUP`
- 확인: `phone:reservation:{phone}:SIGNUP`
- 삭제: 회원가입 성공 시 위 두 key

## 예외 조건

- `VALIDATION_ERROR`: 필수값 누락, 비밀번호 불일치, 형식 오류
- `CONFLICT`: loginId, nickname, phone, email 중복
- `VALIDATION_ERROR`: 전화번호 인증 미완료

## 구현 체크리스트

- [ ] 회원가입 성공 후 Set-Cookie 없음
- [ ] verified/reservation 소비
- [ ] phoneVerificationId 사용 안 함
