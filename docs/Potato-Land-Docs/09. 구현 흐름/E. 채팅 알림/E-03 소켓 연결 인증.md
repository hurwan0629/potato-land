# E-03 Socket 연결 인증·재연결

## Frontend 순서

1. 로그인 성공 뒤 `withCredentials: true`로 Socket.IO를 연결한다.
2. 연결 성공 후 필요한 개인 알림 listener를 한 번만 등록한다.
3. 현재 화면이 채팅/경매면 해당 room join을 다시 보낸다.
4. access 만료 오류면 HTTP refresh를 한 번 호출한 뒤 재연결한다.
5. refresh 실패, 정지, 탈퇴이면 자동 재연결을 중단하고 로그인 상태를 비운다.
6. 재연결 후 알림 unread count와 현재 화면 HTTP 데이터를 재조회한다.

## Backend 연결 순서

1. handshake cookie의 `access_token`을 읽는다. fallback auth token은 프론트 제약이 확인된 경우에만 사용한다.
2. JWT 서명·만료·`type=access`를 검증한다.
3. `sub`로 DB 사용자를 조회해 `deleted_at`, `banned_at`, 현재 role을 확인한다.
4. 비활성 사용자는 연결을 거부한다.
5. 최소 인증 정보만 `socket.data.auth`, 사용자 요약을 `socket.data.user`에 둔다.
6. `activeChatRoomIdx`, `activeAuctionListingIdx`를 null로 초기화한다.
7. 개인 room `user:{userIdx}`에 join한다.
8. 연결 성공 뒤 unread count를 DB에서 조회해 전송할 수 있다.

## 강제 종료

- 회원 탈퇴·영구정지 commit 후 해당 `user:{userIdx}` 연결을 찾고 강제 종료한다.
- 서버는 클라이언트의 room 목록을 Redis에 복제하지 않는다.
- 한 사용자의 여러 기기 연결은 각각 개인 room에 join하며, active 화면 상태도 Socket별로 판단한다.
- 하나의 Socket은 개인 room과 chat 또는 auction 활성 room 하나만 유지한다. 새 화면 join 시 기존 반대 room을 leave하고 active id를 정리한다.
