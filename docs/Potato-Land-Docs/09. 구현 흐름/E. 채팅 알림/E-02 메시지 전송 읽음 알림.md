# E-02 메시지 전송·읽음·메시지 알림

## 요청 계약

- 텍스트 전송: `chat:message:send`
- 이미지 전송: `POST /api/chats/:chatRoomIdx/messages/images`
- 읽음: `chat:read`

텍스트 payload는 `clientMessageId`, `chatRoomIdx`, `messageType=TEXT`, `content`를 사용한다. `clientMessageId`는 클라이언트가 생성한 UUID다.

## Frontend 순서

1. 전송마다 새 `clientMessageId`를 만들고 임시 메시지를 표시한다.
2. ack 전까지 같은 id의 재전송 버튼을 잠근다.
3. 성공 ack의 `messageIdx`로 임시 메시지를 확정한다.
4. 동일 id 또는 messageIdx의 `chat:message:new`은 중복 추가하지 않는다.
5. 현재 방에서 새 메시지를 렌더링한 뒤 마지막 messageIdx로 `chat:read`를 보낸다.
6. 실패 ack면 임시 메시지를 실패 상태로 표시하고 같은 id를 이용한 명시적 재시도만 허용한다.

## 텍스트 메시지 Backend 순서

1. Socket 사용자, payload 형식, `TEXT`, 길이를 검증한다.
2. DB에서 채팅 참여자와 E-01의 쓰기 가능 상태를 확인한다.
3. `(chat_room_idx, sender_idx, client_message_id)`를 조회한다.
4. 이미 있으면 기존 메시지 성공 ack를 반환하고 새 row와 알림을 만들지 않는다.
5. transaction에서 `chat_messages`를 저장하고 `chat_rooms.updated_at`을 갱신한다.
6. 수신자의 현재 서버 Socket 연결 중 `activeChatRoomIdx`가 해당 방인지 확인한다.
7. 보고 있지 않을 때만 `NEW_MESSAGE` 알림을 transaction에 저장한다.
8. commit 후 방에 `chat:message:new`, 양 개인 room에 `chat:room:updated`를 보낸다.
9. 저장된 알림이 있으면 수신자에게 `notification:new`과 DB에서 계산한 절대 unread count를 보낸다.
10. sender에게 성공 ack를 보낸다.

## 이미지 메시지

HTTP 인증·참여자·쓰기 가능 상태와 파일을 검증하고 storage에 저장한다. transaction에서 `IMAGE` 메시지와 조건부 알림을 저장한 뒤 commit 후 텍스트와 동일한 Socket 이벤트를 보낸다. DB rollback이면 새 파일을 best-effort로 정리한다.

## 읽음 처리

1. `chat:read`의 사용자가 참여자인지 확인한다.
2. `lastMessageIdx`가 해당 방에 존재하고 사용자가 볼 수 있는 범위를 넘지 않는지 확인한다.
3. transaction에서 `chat_room_reads.last_read_message_idx`를 더 큰 값으로만 갱신한다.
4. 해당 방에 연결된 저장 `NEW_MESSAGE` 알림을 읽음 처리한다.
5. commit 후 읽은 사용자에게 절대 unread count, 상대에게 `chat:read:updated`를 전송한다.

## 실패 원칙

- DB 실패 시 성공 ack와 어떤 새 메시지 이벤트도 보내지 않는다.
- Socket emit 실패 시 DB 메시지는 유지되며 메시지 HTTP 재조회로 회복한다.
- `activeChatRoomIdx`는 알림 row 생략에만 사용하며 메시지 저장 여부에는 영향이 없다.
