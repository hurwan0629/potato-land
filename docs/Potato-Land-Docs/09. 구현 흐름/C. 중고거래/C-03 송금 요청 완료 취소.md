# C-03 송금 요청 완료 취소

## 목적

판매자가 구매자에게 송금 요청을 만들고, 구매자가 송금 완료 처리한다.

## Frontend 구현 흐름

- 판매자 채팅방에서 송금 요청 버튼을 제공한다.
- 판매자가 송금 요청을 만들면 구매자 채팅방에 송금 페이지 이동 버튼을 표시한다.
- 구매자는 송금 페이지에서 송금 후 완료 버튼을 누른다.
- 송금 페이지에서 돌아가기/취소는 화면 이동 취소이며, 거래 취소가 아니다.
- 판매자가 송금 요청을 취소하면 거래 상태는 `CANCELED`가 된다.

## Backend 구현 흐름

- 판매자만 송금 요청을 생성할 수 있다.
- 같은 판매자가 같은 구매자에게 같은 게시글 기준으로 동시에 2개 이상의 `REQUESTED` 거래를 만들 수 없다.
- 송금 요청 생성 시 `transactions` row를 `REQUESTED`로 저장한다.
- 송금 요청 메시지를 `chat_messages`에 `PAYMENT_REQUEST`로 저장한다.
- 구매자에게 `PAYMENT_REQUESTED` 알림과 `chat:message:new`을 전송한다.
- 구매자만 송금 완료 처리할 수 있다.
- 판매자만 송금 요청을 `CANCELED`로 취소할 수 있다.
- 참여자 중 한 명이 비활성화되면 `REQUESTED` 거래는 `CANCELED`가 된다.

## 예외 조건

- `FORBIDDEN`: 권한 없음
- `CONFLICT`: 이미 REQUESTED 거래 존재, 이미 완료/취소
- `INACTIVE_USER`: 참여자 비활성
