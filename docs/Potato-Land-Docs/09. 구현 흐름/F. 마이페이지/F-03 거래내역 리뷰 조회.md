# F-03 거래내역·후기 조회

## 요청 계약

내 거래내역과 후기 API에 상태·역할·검색·pagination query를 전달한다. 인증 쿠키가 필수다.

## Frontend 순서

1. 거래 상태·역할·검색·page를 query로 보낸다.
2. `REQUESTED`, `COMPLETED`, `CANCELED`를 서버 응답 그대로 표시한다.
3. `canWriteReview=true`인 완료 거래만 후기 버튼을 표시한다.
4. 삭제 상품은 snapshot을 보여주고 `detailLinkEnabled=false`를 따른다.
5. 거래/후기 변경 이벤트를 받으면 현재 페이지를 재조회한다.

## Backend 조회 순서

1. 인증·활성 사용자와 query를 검증한다.
2. `seller_idx = actor OR buyer_idx = actor` 조건을 강제한다.
3. listing과 대표 이미지의 현재값 또는 보존 가능한 snapshot을 조합한다.
4. 각 transaction에 현재 사용자가 작성한 review 존재 여부를 함께 조회한다.
5. `status=COMPLETED`, 상대방 존재, 내 review 없음일 때만 `canWriteReview=true`로 계산한다.
6. rating은 1~10 원본으로 응답한다.
7. 생성일과 idx로 안정적인 pagination을 적용한다.

## 무결성 체크

- [ ] 참여 거래만 조회
- [ ] 거래 상태를 화면에서 임의 변경하지 않음
- [ ] `(transactionIdx, reviewerIdx)`로 후기 가능 여부 계산
- [ ] 삭제 상품 상세 링크 차단
- [ ] rating 원본 유지
