# F-01 내 마이페이지 조회

## Frontend 순서

1. 탭별 API를 필요한 시점에 호출하고 page/filter를 query로 보낸다.
2. 프로필 요약, 판매상품, 관심목록, 거래내역, 후기를 서로 독립적으로 로딩한다.
3. 응답의 삭제·링크·권한 필드를 사용하고 화면에서 상태를 재추론하지 않는다.
4. rating/averageRating은 `/ 2`해 표시한다.

## Backend 조회 순서

1. 인증·활성 사용자를 확인한다.
2. 프로필 요약은 `users`와 거래/후기 aggregate를 조회한다.
3. 판매상품과 관심목록은 `listings.deleted_at IS NULL`을 강제한다.
4. 거래내역은 seller/buyer가 현재 사용자인 row만 조회하고 삭제 listing도 snapshot DTO로 포함한다.
5. 후기는 reviewer/reviewee 관계와 query type에 맞춰 조회한다.
6. 각 목록은 DB pagination과 안정적인 보조 정렬(`idx`)을 사용한다.
7. N+1 대신 join/aggregate/select-in 형태로 필요한 관계를 한 번에 조회한다.

## 저장소와 동기화

- PostgreSQL만 사용한다. 마이페이지 전용 Redis 캐시는 두지 않는다.
- 수정·거래·후기 성공 후 프론트가 관련 탭을 invalidate/re-fetch한다.
- Socket 알림은 재조회 신호일 뿐 마이페이지 원본을 직접 변경하지 않는다.
