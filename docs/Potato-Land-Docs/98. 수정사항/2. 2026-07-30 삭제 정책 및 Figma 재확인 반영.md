# 2026-07-30 삭제 정책 및 Figma 재확인 반영

## 반영 기준

- Figma CSS 덤프 최신본: `08. UI 참고/Figma CSS 덤프 - 메인 마이페이지 판매상품 GETmypageid`
- 사용자 확정 정책:
  - 구매자 후기와 판매자 후기는 양방향 모두 가능하다.
  - 게시글/경매의 취소 상태는 사용하지 않고 삭제는 `deleted_at`으로 처리한다.
  - 삭제 주체 추적을 위해 `deleted_by`를 둔다.
  - 거래 송금 요청 취소만 `transactions.status = CANCELED`를 사용한다.
  - 회원 정보 수정 진입 전 비밀번호 인증을 요구한다.
  - 회원 정보 수정에서는 새 전화번호 인증, 비밀번호, 닉네임, 이메일 변경을 지원한다.
  - 관리자의 회원 삭제 UI는 실제 DB 삭제가 아니라 영구정지 처리다.

## Figma 재확인 결과

- 회원 정보 수정 화면은 바로 폼을 보여주는 방식이 아니라 비밀번호 확인 후 수정 화면으로 이동하는 흐름으로 확인했다.
- 회원 정보 수정 화면에는 새 비밀번호, 새 비밀번호 확인, 전화번호 인증, 저장 버튼 활성화 조건이 포함되어 있다.
- 마이페이지와 상대방 프로필의 후기 영역에는 구매자 후기와 판매자 후기가 모두 표현되어 있다.
- 판매자가 채팅에서 송금 요청을 만들고, 구매자가 해당 송금 요청 화면에서 송금하는 흐름을 기준으로 문서화했다.
- Figma CSS 원문에는 과거의 `거래 취소`, `취소` 표현이 일부 남아 있으나 구현 기준 문서에서는 게시글/경매 취소 상태로 해석하지 않는다.

## 삭제 또는 의미 변경한 항목

- 게시글/경매 `CANCELED` 상태는 사용하지 않는다.
- `PATCH /api/used/:listingIdx/cancel`은 사용하지 않는다.
- `PATCH /api/auctions/:listingIdx/cancel`은 사용하지 않는다.
- `auction:canceled` Socket 이벤트는 사용하지 않는다.
- 범용 `POST /api/uploads/images`는 사용하지 않는다.
- 채팅 텍스트 메시지 전송용 HTTP API는 사용하지 않는다.

## 유지한 항목

- `transactions.CANCELED`
  - 판매자가 이미 생성한 송금 요청을 취소했을 때만 사용한다.
- `users.banned_until`
  - MVP에서는 사용하지 않지만 DB 컬럼은 유지한다.
- Figma CSS 덤프 원문
  - 원문 비교를 위해 수정하지 않는다.

## 남은 주의점

- Figma CSS 원문에 남아 있는 `거래 취소`, `취소` 표현은 구현 명세와 다를 수 있다.
- 실제 구현 시에는 Figma 원문보다 이 문서 세트의 상태 정책과 API 명세를 우선한다.
- 관리자 대시보드 통계 항목은 아직 최종 확정 전이다.
- SMS 제공자, 배포 환경, Redis Lua/Worker 구현 세부는 개발 중 학습 및 구현 난이도에 따라 범위를 조정할 수 있다.
