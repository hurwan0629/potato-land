# 프론트엔드 연결 상태

## API client 존재

| client | 범위 | 상태 |
|---|---|---|
| `authApi.js` | 회원가입/인증/로그인/복구 | 존재 |
| `usersApi.js` | 비밀번호 확인, 수정, 탈퇴 | 존재하나 `editToken` 구현에 결합 |
| `auctionsApi.js` | 목록/상세/등록/수정/삭제 | 존재. 입찰/관심 없음 |
| `chatApi.js` | 채팅 HTTP | 존재 |
| `transactionsApi.js` | 거래 | 존재 |
| `notificationsApi.js` | 알림 | 존재 |
| `http.js` | cookie, 401 refresh single-flight | 존재 |

## 없는 주요 client

- main/categories
- used
- mypage
- reviews
- admin

## 확인된 계약 결합

[`client/src/api/usersApi.js`](https://github.com/hurwan0629/potato-land/blob/061e78c2bcd039191277b211a51fd08bb1669feb/client/src/api/usersApi.js)는 서버의 비문서 계약인 `editToken`을 그대로 사용한다. 즉 프런트와 현재 백엔드는 맞을 수 있지만, 둘 다 기준 문서와 어긋난 상태다.

[`client/src/api/auctionsApi.js`](https://github.com/hurwan0629/potato-land/blob/061e78c2bcd039191277b211a51fd08bb1669feb/client/src/api/auctionsApi.js)는 등록·수정 시 FormData를 보내지만 backend auction router에는 multer가 없어 이미지가 전달되지 않는다.

[`client/src/api/http.js`](https://github.com/hurwan0629/potato-land/blob/061e78c2bcd039191277b211a51fd08bb1669feb/client/src/api/http.js)는 401이면 `/auth/refresh` 후 원 요청을 한 번 재시도한다. 구조 자체는 적절하다.

## 화면 구현 상태의 정적 징후

상대적으로 큰 파일:
- 채팅 페이지
- 회원가입/계정 복구
- 로그인
- 경매 목록/상세/폼

매우 작은 placeholder 수준:
- 마이페이지
- 결제
- 상품 상세
- 상품 등록
- 검색
- 관리자

빈 공통 컴포넌트:
- `DropDown.jsx`
- `RatingStar.jsx`
- `SearchBar.jsx`

프런트 구현도는 이 감사의 68개 backend API 점수에는 포함하지 않았지만, 전체 사용자 흐름 완성에는 직접적인 병목이다.
