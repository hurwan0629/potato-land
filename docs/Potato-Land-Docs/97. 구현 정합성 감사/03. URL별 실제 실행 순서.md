# URL별 실제 실행 순서

> [!note]
> 이 문서의 순서는 정적 호출 그래프다. Express middleware, controller, service, repository, DB/Redis/Socket 후처리를 실제 코드에서 따라갔다. 한 파일 안에서 직접 SQL을 실행하는 경우도 그대로 적었다.

### 1. `POST /api/auth/signup` — 회원가입

- 판정: 🟡 **부분 구현**
- 위치: `backend/src/modules/auth/auth.router.js → auth.controller.js#signup`
- 실제 순서: `app.js → apiRouter → authRouter → asyncHandler(signup) → validateSignup → signupUser → Redis 가입 인증 확인 → 중복 조회 → bcrypt → DB transaction(createUser) → 201`
- 차이: 기능은 동작하나 문서 오류 코드·응답 DTO 일부 불일치.

### 2. `GET /api/auth/check-id` — 아이디 중복 확인

- 판정: 🟡 **부분 구현**
- 위치: `backend/src/modules/auth/auth.router.js → auth.controller.js#checkLoginId`
- 실제 순서: `app.js → apiRouter → authRouter → checkLoginId → validateLoginId → checkLoginIdAvailability → auth.repository.findUserByLoginId → 200`
- 차이: 실행 가능. 문서와 세부 오류 코드/메시지 정합성은 완전하지 않음.

- 판정: 🟡 **부분 구현**
- 위치: `backend/src/modules/auth/auth.router.js → auth.controller.js#sendPhoneCode`
- 실제 순서: `app.js → apiRouter → authRouter → sendPhoneCode → validatePhoneSend → sendPhoneVerification → Redis cooldown/rate-limit → SMS provider → Redis code 저장 → 200`
- 차이: 인증번호와 SMS 본문이 로그에 평문 노출됨. 응답 DTO도 문서와 다름.
