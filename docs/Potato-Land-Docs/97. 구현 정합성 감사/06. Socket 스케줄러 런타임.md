# Socket·스케줄러·런타임

## 서버 시작

[`backend/src/server.js`](https://github.com/hurwan0629/potato-land/blob/061e78c2bcd039191277b211a51fd08bb1669feb/backend/src/server.js)의 실제 순서:

1. `http.createServer(app)`
2. `createSocketServer(httpServer)`
3. `app.set("io", socketServer.io)`
4. 개발용 SMS provider 등록
5. `connectDatabase()`
6. `connectRedis()`
7. `httpServer.listen()`

## 서버 종료

`SIGINT`/`SIGTERM → stopAuctionRecoveryScheduler → clearAuctionTimers → Socket close + Redis disconnect + DB close`

종료 순서는 있으나 시작 시 recovery scheduler는 호출되지 않는다.

## Socket 구현도

| 구분 | 이벤트 | 상태 |
|---|---|---|
| 인증 | handshake access token, DB 상태, `user:<built-in function id>` join | 구현 |
| 채팅 inbound | join, leave, message send, read | 구현 |
| 채팅 outbound | message:new, room:new, room:updated | 구현 |
| 알림 outbound | notification:new, unread-count | 구현 |
| 경매 inbound | auction:join, auction:leave | 501 ACK |
| 경매 bid | HTTP 입찰 자체가 501 | 미구현 |
| 경매 outbound helper | bid/leader/end/won/outbid emitter 파일 | helper만 있고 실제 핵심 호출 흐름 없음 |

## 상태 저장

- `socket.data.activeChatRoomIdx`: 구현
- `socket.data.activeAuctionListingIdx`: 초기화만 되고 auction join이 501
- 개인 room: 구현
- 채팅 room: 구현
- 경매 room: 미구현
