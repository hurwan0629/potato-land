# 테스트·CI·검증 한계

## 확인된 테스트

`backend/test`:
- auctions validator
- auth token
- auth validator
- users validator

`backend/tests`:
- auctionTimer
- error middleware
- logger
- redisKey

총 8개 파일이며 validator·공통 유틸 중심이다.

## CI

[`.github/workflows/backend-ci.yml`](https://github.com/hurwan0629/potato-land/blob/061e78c2bcd039191277b211a51fd08bb1669feb/.github/workflows/backend-ci.yml)는 다음을 수행한다.

1. PostgreSQL 17 service
2. Redis 7 service
3. Node 24
4. `npm ci`
5. `npm run db:setup`
6. `npm test`

CI 기반은 있으나 업무 API integration test가 없으므로 `npm test`가 성공해도 35개 미구현 URL과 문서 DTO 불일치를 잡지 못한다.

## 이번 감사가 한 일

- 브랜치 HEAD와 recursive tree 확인
- 기준 문서와 라우터 대조
- controller/service/repository/Redis/Socket/scheduler/DB migration 정적 추적
- 68개 URL별 실제 호출 경로 분류
- 프런트 API client와 backend URL 대조
- CI와 테스트 파일 범위 확인

## 이번 감사가 하지 못한 일

- 실제 `npm test` 실행
- PostgreSQL/Redis를 띄운 E2E
- 동시 입찰 race test
- 실제 SMS 발송
- 브라우저 UI 수동 테스트
- GitHub Actions run 결과 검증
- production environment 변수 검증

실행 환경에서 저장소 checkout 네트워크가 제한되어 GitHub connector의 읽기 API로 고정 커밋을 분석했다. 따라서 점수는 **정적 구현 감사**이며, 런타임 성공률이 아니다.
