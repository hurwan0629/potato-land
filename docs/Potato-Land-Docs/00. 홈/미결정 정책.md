# 미결정 정책

> 지금 결정하지 않아도 구현을 시작할 수 있지만, 구현 전 또는 구현 중 한 번은 팀에서 확인해야 하는 항목이다.

## 1. 인증

- [x] Access Token 쿠키 path를 `/`로 둘지 `/api`로 제한할지 결정
- [x] Refresh API 경로를 `/api/auth/refresh`로 할지 `/api/refresh`로 할지 결정
- [x] Refresh Token rotation을 MVP에서 적용할지 결정
- [x] 여러 기기 동시 로그인을 허용할지 결정
- [x] 비밀번호 찾기에서 임시 비밀번호 발급과 재설정 링크 중 어떤 방식을 쓸지 결정

## 2. 전화번호 인증

- [x] 문자 발송 서비스 선택: CoolSMS 또는 SolAPI
- [x] 인증번호 재발송 대기 시간 결정
- [x] 인증번호 최대 검증 시도 횟수 결정
- [x] 개발 환경에서 실제 문자 발송 대신 콘솔/테스트 코드로 처리할지 결정

## 3. 경매

- [x] 입찰 단위 산정 방식 결정: 현재가 구간별 단위, 100만원 이상은 1%를 1,000원 단위 올림
- [x] 경매 기본 진행 시간 결정: 현재 후보는 `started_at + 24h`
- [x] Redis Lua script를 MVP에서 직접 구현할지 결정
- [x] Redis Stream + Worker를 MVP에 포함할지, 확장 항목으로만 둘지 결정
- [x] DB 저장 실패 시 입찰 성공 상태를 취소할지 재시도할지 결정
- [x] 삭제된 경매의 기존 입찰 내역 보존 여부 결정: DB에는 보존하고 일반 사용자 화면에서는 삭제 경매를 조회하지 않음

## 4. 채팅/알림

- [x] 채팅방을 중고거래 문의 시 생성할지, 경매 낙찰 후 자동 생성할지 화면별 확정
- [x] 같은 채팅방을 보고 있는 사용자의 메시지 알림을 즉시 읽음 처리할지 결정
- [x] 알림 보관 기간 또는 삭제 정책 결정
- [x] 읽음 처리 단위를 알림 1건으로 할지 전체 읽음으로 할지 결정

## 5. 관리자

- [x] 정지 사용자 기존 게시글/채팅 접근 제한 범위 결정
- [x] 정지된 판매자의 기존 게시글/경매를 삭제할지, 조회만 제한할지 결정
- [ ] 관리자 대시보드 통계 항목 최종 확정
