# 설계 결정사항

> 이 문서는 2026-07-29 기준 확정 또는 준확정된 프로젝트 방향을 정리한다. 구현 중 바뀌는 내용은 각 기능 명세와 함께 갱신한다.

## 1. 프로젝트 범위

- 서비스명: 감자나라
- 주 기능: 중고거래, 경매, 채팅, 알림, 마이페이지, 관리자
- 문서화 목표: 기능 명세, 전체 플로우, API, Socket 이벤트, 서버 아키텍처, Mermaid 다이어그램, 구현 체크리스트
- 설계 기간: 2026-07-29 ~ 2026-08-02
- 구현/브랜치/병합/동작 목표: 2026-08-09

## 2. 서버 기술 스택

- Runtime: Node.js
- Server: Express
- DB: PostgreSQL
- Cache/Realtime State: Redis
- Realtime: Socket.IO
- Scheduler: Node 서버 내부 cron 기반 스케줄러
- Upload: multer 기반 local `/uploads`
- 배포: `.env` 기반 환경변수 분리, Docker Compose 적용 가능 구조 지향

## 3. 후순위 확장 항목

- S3 또는 S3-compatible object storage
- Load Balancer
- Socket.IO Redis adapter
- Redis Stream + Worker 기반 비동기 입찰 저장
- TypeScript 전환
- 고급 통계 대시보드

## 4. 인증 정책

- Access Token과 Refresh Token은 모두 쿠키로 전달한다.
- Access Token 만료 시간은 15분이다.
- Refresh Token 만료 시간은 7일이다.
- Refresh Token 쿠키는 `/api/auth/refresh` 또는 `/api/refresh` 경로로 제한한다.
- 쿠키는 HttpOnly를 기본으로 한다.
- 배포 환경에서는 Secure 쿠키를 사용한다.
- 로그아웃 시 access token과 refresh token 쿠키를 모두 만료시킨다.
- Refresh Token 유효성은 Redis TTL과 함께 관리한다.
- 정지 사용자는 로그인, 토큰 재발급, 보호 API 접근을 차단한다.

## 5. Redis 사용 정책

- Refresh Token 유효성 관리
- 전화번호 인증번호와 인증 완료 식별자 관리
- 경매 현재 최고 입찰 상태 관리
- Socket.IO 접속 사용자 상태 보조
- Redis 장애 시 신규 입찰은 차단한다.
- Redis 상태는 PostgreSQL 기준으로 복원 가능해야 한다.
- 최종 영속 데이터 기준은 PostgreSQL이다.

## 6. 경매 정책

- 경매 현재가와 최고 입찰자는 Redis에서 빠르게 확인한다.
- 입찰 성공 시 PostgreSQL에도 입찰 내역을 저장한다.
- 현재 구현 목표는 Redis 갱신 후 DB 즉시 저장이다.
- Redis Stream + Worker는 확장 구조로 문서화하고, 구현 여유가 있을 때 적용한다.
- 입찰 비교와 최고 입찰자 갱신은 Redis Lua script 또는 동등한 원자 처리로 보장한다.
- 경매 종료는 서버 스케줄러가 확정한다.
- 프론트엔드는 카운트다운 표시만 담당한다.

## 7. 관리자 정책

- 관리자는 사용자를 영구정지할 수 있다.
- 사용자 삭제는 하지 않는다.
- `users.banned_at IS NOT NULL`이면 정지 사용자로 본다.
- `banned_until`은 MVP에서 사용하지 않는다. 값이 NULL인 정지는 영구정지로 해석한다.
- 게시글 숨김과 삭제 기능은 없다.
- 게시글과 경매는 취소 상태만 사용한다.
- 진행 중인 경매 주최자가 영구정지되면 해당 경매는 취소 처리한다.
- 취소된 경매는 관심 추가, 입찰, 채팅 버튼을 비활성화한다.
- 과거 입찰자에게는 사용자가 정지되었다고 말하지 않고 "경매가 취소되었습니다" 알림을 보낸다.

## 8. 알림 정책

- 모든 알림은 DB `notifications`에 먼저 저장한다.
- 사용자가 Socket.IO에 접속 중이면 실시간 이벤트도 함께 보낸다.
- 사용자가 접속 중이지 않으면 DB의 `is_read=false` 상태로 남긴다.
- 사용자가 해당 채팅방을 보고 있는 상태에서 상대방 메시지가 오면 새 메시지 알림은 즉시 읽음 처리할 수 있다.
- 경매 상세 화면을 보고 있는 사용자는 해당 경매의 실시간 이벤트를 Socket으로 받는다.

## 9. 파일 업로드 정책

- MVP는 multer로 서버 local `/uploads`에 저장한다.
- DB에는 `post_images.image_url` 문자열만 저장한다.
- S3 전환을 고려해 storage service 계층을 둔다.
- 구현 초반에는 local storage 구현체만 만든다.

## 10. 문서 작성 원칙

- 기능 명세는 용어를 풀어쓴다.
- 명세 수준은 낮추지 않는다.
- 미확정 내용은 임의 확정하지 않고 `미결정 정책.md`에 모은다.
- 개발자가 바로 체크할 수 있도록 각 문서에 체크리스트를 둔다.
